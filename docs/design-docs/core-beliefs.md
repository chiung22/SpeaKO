# Core Beliefs

SpeaKO AI 서버의 코드베이스를 읽어보면 명시적으로 문서화되어 있지 않았을 뿐, 실제로는 아래 원칙들이 이미 일관되게 적용되어 있었습니다. 이 문서는 그 원칙을 명문화한 것입니다.

## 1. 외부 API는 언제든 실패할 수 있다는 것을 전제로 설계한다

HyperCLOVA X, ETRI, g2pkk, Clova Voice, Azure Speech — 이 5개 외부 의존성 전부 API 키가 없거나 호출이 실패했을 때 **서버를 죽이지 않고 모의(mock) 데이터나 fallback 사전으로 대체**합니다.

**왜:** 프론트엔드/통합 개발이 실제 유료 API 키 발급을 기다리지 않고도 전체 파이프라인을 처음부터 끝까지 시연할 수 있어야 하기 때문입니다. `run_pipeline_test.py`가 API 키 없이도 끝까지 실행되는 것이 이 원칙이 지켜지고 있다는 증거입니다.

**적용 방법:** 새 외부 연동을 추가할 때는 반드시 "키 없음/호출 실패" 케이스에서 무엇을 반환할지부터 설계하세요. 예외를 던져서 500을 내는 것은 이 원칙 위반입니다.

## 2. LLM 출력 포맷은 토큰 비용을 최우선으로 고려한다

`FullScriptGenerator`/`PartialScriptGenerator`는 JSON 대신 자체 TOON 포맷(`slides[N]{slide_number,script}:`)을 시스템 프롬프트로 강제합니다. 반복되는 키 이름을 없애 출력 토큰을 40% 이상 절감한다고 설계 문서([docs/references/hyperclova_prompt_guide.md](../references/hyperclova_prompt_guide.md))에 명시되어 있습니다.

**왜:** 대본 생성은 슬라이드 수에 비례해 출력 토큰이 늘어나는 구조라, 포맷 낭비가 곧바로 비용으로 직결됩니다.

**적용 방법:** LLM 응답 포맷을 바꾸거나 새로 추가할 때, JSON을 기본값으로 쓰기 전에 반복 구조를 압축할 수 있는지 먼저 검토하세요.

## 3. 실패는 HTTP 상태코드로 정직하게 알린다

API 실패를 200 OK + `{"success": false}`로 감추지 않고 4xx/5xx로 구분합니다 (외부 API 실패는 502, 잘못된 입력은 422 등). 이렇게 해야 프론트엔드가 재시도/에러 UI 분기를 상태코드만으로 처리할 수 있습니다.
