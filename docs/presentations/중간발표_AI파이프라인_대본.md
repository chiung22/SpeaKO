# SpeaKO AI 파이프라인 중간 발표 대본

> PM 발표용. 비전공자도 이해할 수 있도록 기술 용어를 최소화하고, "어떤 API를 왜 썼는지"와 "전체 흐름"을 중심으로 구성했습니다. 필요하면 슬라이드 장수에 맞춰 문단 단위로 빼거나 더 채워 넣으시면 됩니다.

---

## 1. 오프닝 — 우리가 풀려는 문제

안녕하세요, 저는 SpeaKO의 AI 파이프라인 개발 현황을 말씀드릴 PM입니다.

발표 준비할 때 다들 이런 경험 있으실 거예요. PPT는 다 만들었는데, 막상 뭐라고 말해야 할지는 안 정해져 있고, 발표 대본을 쓰더라도 내가 이 단어를 제대로 발음하고 있는지는 아무도 알려주지 않습니다. SpeaKO는 이 두 가지 문제, **"대본이 없다"**와 **"발음 피드백이 없다"**를 AI로 해결하는 서비스입니다.

오늘은 사용자에게 보이는 화면 뒤에서, 실제로 어떤 AI 기술들이 어떻게 연결되어 동작하는지를 말씀드리겠습니다.

## 2. 전체 흐름 한눈에 보기

사용자 입장에서 SpeaKO를 쓰는 과정은 이렇습니다.

1. **발표할 PPT 파일을 올린다**
2. **AI가 슬라이드 내용을 분석해서 발표 대본을 자동으로 써준다**
3. **마음에 안 드는 부분은 다시 써달라고 요청한다**
4. **대본 안에서 발음하기 어려운 단어를 AI가 미리 짚어준다**
5. **사용자가 실제로 소리 내어 읽고 녹음하면, AI가 발음을 채점해준다**

이 다섯 단계 각각에 서로 다른 AI 서비스가 하나씩 붙어 있고, 저희는 이 서비스들을 하나의 파이프라인으로 이어 붙이는 작업을 하고 있습니다.

## 3. 왜 하나가 아니라 여러 개의 AI를 쓰는가

"AI 하나로 다 되는 거 아니야?"라는 질문을 많이 받는데, 그렇지 않습니다. 각 AI 서비스는 잘하는 영역이 명확히 다릅니다.

- **글을 자연스럽게 쓰는 것**을 잘하는 AI가 있고
- **한국어 문장을 문법적으로 정밀하게 쪼개는 것**을 잘하는 AI가 있고
- **사람이 실제로 말한 발음을 채점하는 것**을 잘하는 AI가 따로 있습니다.

그래서 저희는 한 회사의 AI에 다 맡기지 않고, **단계마다 그 일을 가장 잘하는 AI를 골라서 조합**했습니다.

## 4. 단계별로 어떤 AI를, 왜 썼는가

### ① 대본 자동 생성 — 네이버 HyperCLOVA X

PPT에서 뽑아낸 슬라이드별 텍스트를 던져주면, 이 AI가 "발표자가 실제로 말하듯이" 대본을 써줍니다. 한국어로 학습된 국내 AI라서 어색한 번역체가 아니라 자연스러운 한국어 구어체를 만드는 데 강점이 있어서 선택했습니다.

그런데 처음에 나온 대본을 저희가 직접 검토해보니, "~설명합니다" 같은 문장이 마치 AI가 사용자에게 설명하는 것처럼 읽히는 문제가 있었습니다. 그래서 **초안을 한 번 더 같은 AI에게 검토시켜서, 발표자가 청중에게 직접 말하는 어투로 다듬는 단계**를 추가했습니다. 대본 하나가 나오기까지 사실 AI 호출이 두 번 일어나는 셈입니다 — 초안 작성, 그리고 자연스럽게 다듬기.

### ② 부분 재생성

대본 전체가 아니라 특정 슬라이드만 마음에 안 들 수도 있으니, "이 슬라이드만 다시 써줘"라고 요청하면 그 부분만 다시 생성하는 기능도 같은 AI로 구현했습니다.

### ③ 발음 주의 단어 추출 — ETRI 언어분석 API

완성된 대본에서 발음하기 까다로운 단어(외래어, 고유명사, 전문용어 등)를 미리 짚어주는 단계입니다. 국내 연구기관(ETRI)이 제공하는 한국어 형태소 분석 엔진을 사용하는데, 문장을 "명사/동사/외래어" 같은 품사 단위로 정밀하게 쪼개는 데 특화되어 있어서, 어떤 단어가 발음 주의 대상인지 골라내는 데 적합합니다.

### ④ 발음 기호로 시각화

추출된 단어들을 실제 발음(예: "특징" → "특찡")으로 변환해서 사용자에게 미리 보여줍니다. 눈으로 먼저 확인하고 연습할 수 있게 하는 단계입니다.

여기서 한 단계 더 들어가서, 철자와 실제 발음이 다른 단어들을 **왜 다른지**까지 세 가지로 나눠서 보여주도록 했습니다. **장단음**(같은 글자인데 길게/짧게 읽어야 하는 경우), **연음**(받침이 다음 글자로 넘어가서 읽히는 경우), 그리고 나머지 **표기-발음 불일치**입니다. 장단음은 국립국어원이 제공하는 표준국어대사전 데이터를 조회해서 판정하고, 연음은 한글 자모 구조를 직접 분석해서 판정합니다.

### ⑤ 실제 발음 평가 — Microsoft Azure AI Speech

사용자가 대본을 소리 내어 읽고 녹음하면, 그 음성 파일을 분석해서 정확도·유창성·완성도 점수를 매겨줍니다. 이건 "발음 평가"라는 아주 특정한 기능인데, 국내 서비스 중에는 이만큼 정교하게 지원하는 곳이 마땅치 않아서 해외 서비스를 선택했습니다.

개발 중 흥미로운 문제를 하나 발견했는데요, 처음에는 사용자가 녹음 중간에 한 번 크게 쉬면 AI가 "말이 끝났다"고 판단해서 그 이후는 아예 안 듣는 문제가 있었습니다. 실제 발표 연습은 문장 사이사이 숨 고르는 게 자연스러운데 말이죠. 그래서 **녹음을 끝까지 전부 듣고, 사용자가 실제로 어디까지 말했는지 AI가 스스로 판단해서 채점하도록** 구조를 개선했습니다.

### ⑥ 정확한 발음 들려주기 — 네이버 Clova Voice

발음 기호만 보여주는 것보다, "이게 정확한 발음이에요"라고 직접 들려주면 더 확실하겠죠. 그래서 텍스트를 실제 음성으로 합성해주는 기능도 붙여뒀습니다. 다만 아직 실제 서비스 화면에는 연결 전이라, 다음 스프린트 목표 중 하나입니다.

### ⑦ 이미지로만 된 PPT 슬라이드 읽기

일부 PPT는 텍스트가 아니라 이미지(캡처, 다이어그램)로만 되어 있어서 처음에는 그 안의 내용을 대본에 반영하지 못했습니다. 이 문제는 ①에서 쓰는 HyperCLOVA X가 최근 이미지까지 이해하는 기능을 지원하게 되면서, **새로운 서비스 가입 없이 같은 AI로 이미지 속 글자까지 읽어오는 방식**으로 해결했습니다. 정확도를 더 높이기 위해 사용자가 입력하는 발표 주제·목차를 함께 참고 정보로 넣어주는 부분까지 실제 화면 입력값과 연결했습니다.

## 5. 지금까지의 진행 상황

- PPT 업로드부터 대본 생성까지 전체 흐름이 실제 데이터로 동작하는 것을 확인했습니다.
- 발음 평가도 실제 목소리 녹음으로 테스트해서 정확도·유창성 점수가 정상적으로 나오는 것을 확인했습니다.
- 개발 과정에서 실제로 동작하지 않던 버그 몇 가지(대본 생성이 항상 실패하던 문제 등)를 찾아서 고쳤고, 앞으로는 매번 실제 서비스처럼 검증하면서 개발하고 있습니다.
- **생성한 대본과 연습 기록을 데이터베이스에 저장**하기 시작했습니다. 이전에는 요청-응답 한 번으로 끝나서 아무것도 안 남았는데, 이제는 PPT를 올리면 "프로젝트" 단위로 대본·발음 주의 단어·평가 점수가 전부 쌓이고, 지난 기록을 다시 조회할 수 있습니다.
- 외부에서 누구나 API를 호출해 비용을 유발할 수 있던 부분을 막는 **인증 장치**를 추가했고, PR을 올릴 때마다 자동으로 테스트가 도는 **CI**도 구축했습니다.
- 실제 디자인 화면(Figma)을 확보해서 **PPT 없이 주제·목차만으로도 대본을 만들 수 있게**, 그리고 **이미 써둔 대본을 그대로 올려서 발음 코칭만 받을 수 있게** 입력 방식을 넓혔습니다. 음성 파일도 WAV뿐 아니라 MP3·M4A까지 받을 수 있게 했습니다.
- 발음 주의 단어를 장단음·연음·표기-발음불일치 세 가지로 나눠서 보여주는 기능(위 ④)을 추가했습니다.
