## 업로드 폼 입력값 (그대로 입력)

### 텍스트형 (라이브 업로드)

| 입력란 | 값 |
|---|---|
| 제목(주제) | 체육 교수·학습 지도안 발표 |
| 발표 시간 | 10분 |
| 톤 | 격식체(formal) |

가이드라인:
```
교수님과 동료 교생 앞에서 수업 계획을 설명하는 상황입니다.
단원 목표와 차시별 수업 흐름이 잘 드러나게 구성하고,
교육 용어는 지도안에 적힌 그대로 정확하게 사용해주세요.
```

### 이미지형 (미리 올려둘 것)

| 입력란 | 값 |
|---|---|
| 제목(주제) | SpeaKO 서비스 소개 |
| 발표 시간 | 5분 |
| 톤 | 격식체(formal) |

가이드라인:
```
데모데이에서 심사위원에게 서비스를 처음 소개하는 발표입니다.
발표 불안이라는 문제 → SpeaKO의 해결 방식 → 핵심 기능 순서로 설득력 있게 구성하고,
슬라이드에 수치가 보이면 근거로 인용해주세요.
```

> 💡 **가이드라인 자체가 시연 거리입니다.** 라이브 업로드 때 방문자 앞에서 타이핑하고,
> 생성된 대본에 반영된 부분을 짚어주면 "요구사항을 알아듣는다"가 증명됩니다.
> 이미지형의 "수치가 보이면 인용"은 비전 성능 증명용입니다 — 4장 대본의
> "전 세계 인구의 약 75%"가 실제로 이미지에서 읽어낸 수치입니다.

## 🚨 이미지형은 라이브로 업로드하지 마세요

**업로드에만 87초**가 걸립니다. 대본 생성(12초)보다 훨씬 오래 걸리는데, 글자가 없는
슬라이드라 AI가 이미지를 하나씩 읽어야 하기 때문입니다.

부스 방문자는 90초를 기다려주지 않습니다. **project 47을 미리 열어두고 결과 화면부터**
보여주세요.

> "이건 글자가 하나도 없는 발표자료인데, AI가 슬라이드를 눈으로 읽어서 대본을 만든 겁니다.
> 시간이 좀 걸려서 미리 돌려놨습니다."

**라이브 업로드는 텍스트형(33초)으로만** 하세요.

### 왜 더 못 줄였나

병렬 호출로 바꿔봤지만 116초 → 87초가 한계였습니다. 이 구간은 **동시성이 아니라
HCX 레이트리밋에 묶여 있습니다.**

| | 시간 |
|---|---|
| 순차 (원래) | 116초 |
| 동시 4개 | 95.7초 ← 429가 나고 재시도 대기가 23~30초씩 붙음 |
| **동시 2개** | **86.3초** ← 429가 덜 나서 오히려 빠름 |

올릴수록 빨라지는 구간이 아닙니다. 슬라이드당 읽는 이미지 수를 줄이면 빨라지지만
**대본 근거가 통째로 사라집니다** — 가장 큰 이미지는 대개 배경이라 글자가 없고,
본문은 두세 번째 이미지에 들어 있습니다.

| 장당 읽는 수 | 결과 |
|---|---|
| 3장 (현재) | 10장 / 1,425자 |
| 2장 | 9장 / 1,207자 (한 장이 통째로 빔) |
| 1장 | 1장 / 6자 (전멸) |

## 이미지형이 오히려 더 좋은 시연거리입니다

**① 비전이 실제로 읽어냅니다.** 4장 대본의 *"전 세계 인구의 약 75%가 발표 불안을
경험한다"* 는 **슬라이드 이미지에서 읽어낸 수치**입니다. 원문 텍스트에는 없습니다.

**② 근거가 없으면 지어내지 않습니다.**

```
1장 원문: "SpeaKO / PM-day"  ← 제목뿐
   → "…보시는 바와 같이 현재 슬라이드에는 해당 제목들이 기재되어 있으며…"

6장 원문: "SpeaKO"  ← 한 단어
   → "…본 슬라이드에서는 화면을 통해 정리해 보았습니다…"
```

"이미지만 있으면 헛소리하지 않나요?"라는 질문에 이 두 장이 답입니다.

## 시연 직전 점검

프로덕션에서 아래 9개를 전부 확인했습니다(2026-08-16, 9/9 통과).

| 기능 | 확인된 값 |
|---|---|
| 프로젝트 상세 + 전체 대본 | 18장 / 7,346자 |
| 발음 주의 단어 + 위치 | 16개 / 149곳 |
| 슬라이드 부분 재생성 | 정상 |
| 화자 목록 | 4명 (동현·대성·혜리·고은) |
| 발음 듣기 (TTS) | MP3 정상 |
| docx 다운로드 2종 | 대본 41KB / 하이라이팅 42KB |
| 상세 피드백 생성 | 총평 + 팁 4개 + 감점요인 2개 |
| 슬라이드 썸네일 | 18/18장 |
| 코칭 내역 목록 | 정상 |

당일 아침에 다시 돌리려면:

```bash
ssh -i ~/.ssh/speako-key.pem ubuntu@13.209.87.115
sudo docker exec speako-ai python /tmp/smoke.py     # 스크립트가 남아 있을 때
sudo docker ps                                       # 컨테이너 살아있는지
```

## 백업 (인터넷·API가 죽을 때)

부스 자료 지침대로 **정상 동작 화면을 미리 녹화**해두세요. 특히 이미지형은 어차피
라이브로 못 돌리니, 녹화본이 있으면 그대로 대체할 수 있습니다.

녹화할 장면 세 개:
1. 텍스트형 업로드 → 대본 생성 완료
2. 발음 주의 단어 클릭 → 발음 재생
3. 녹음 평가 → 점수 + 하이라이팅 결과
