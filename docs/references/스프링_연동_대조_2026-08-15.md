# 스프링 ↔ AI 서버 연동 대조 (2026-08-15)

> EC2에 배포된 스프링 JAR(`SpeakO-0.0.1-SNAPSHOT.jar`, 2026-08-14 19:38)을 `javap`으로 직접
> 뜯어서 대조한 결과입니다. **추측이 아니라 배포된 바이트코드에서 읽은 값**입니다.
>
> 대조 대상: `AiPresentationResponseDto`, `AiEvaluationResponseDto`(+중첩 3개),
> `PresentationService`, `EvaluationService`, `Presentation`/`Evaluation` 엔티티.

---

## 요약

| | 상태 |
|---|---|
| 발표 생성(`POST /api/projects` → `/api/script/full` → job 폴링) | ✅ 필드 이름 전부 일치 |
| 단어별 결과 + 하이라이팅 좌표(`words_detail`) | ✅ **이미 파싱 가능** |
| `ai_project_id` 저장 | ✅ **코드 정상** — null은 옛 데이터 |
| 부분 녹음 기준 대본 | ⚠️ `slide_number`·`reference_text` 둘 다 안 보냄 → **점수 왜곡** |
| 발표 습관 지표(`speech_metrics`) | ❌ DB 컬럼은 있는데 DTO에 필드가 없음 (우선순위 밖이면 무시 가능) |
| 감점 요인(`deductions`) / 하이라이팅 묶음(`highlights`) | ❌ DTO에 필드 없음 (하이라이팅은 `words_detail`로 대체 가능) |

**결론부터.** 실제로 손봐야 하는 건 **부분 녹음 기준 대본 하나**입니다. 나머지는 정상이거나
현재 우선순위(대본 생성 결과 → 하이라이팅 → 상세 피드백 → 다운로드) 밖입니다.

## ✅ 이미 맞는 것 — 손대지 마세요

**어투 값이 일치합니다.** `Presentation.Tone` enum이 `formal` / `casual`(소문자)이고,
AI 서버의 `StyleValue`도 `formal`/`casual`을 받습니다.

**대본 생성 흐름의 키 이름이 전부 맞습니다.** `PresentationService`가 쓰는 문자열:
`project_id`, `data`, `slides`, `slide_number`, `script`, `presentation_time`, `style`,
`extra_requirement`, `topic`, `job_id`, `status`, `completed`, `failed`, `error`, `detail`
— AI 서버 응답과 그대로 대응합니다.

**`words_detail`은 하이라이팅 좌표까지 이미 파싱됩니다.** `WordDetail`에 이 네 개가 있습니다.

```java
@JsonProperty("accuracy_score")   private Float accuracyScore;
@JsonProperty("error_type")       private String errorType;
@JsonProperty("reference_span")   private List<Integer> referenceSpan;
@JsonProperty("recognized_span")  private List<Integer> recognizedSpan;
```

AI 서버가 보내는 이름·타입과 **정확히 같습니다**(`[시작, 끝]` 정수 2개).
즉 **하이라이팅은 DTO를 안 고쳐도 `words_detail`만으로 그릴 수 있습니다.**
`error_type`이 `Omission`이면 원본 텍스트에, `Insertion`이면 인식 텍스트에 칠하면 됩니다.

## ✅ 1. `ai_project_id` — 스프링 코드는 정상입니다 (고칠 것 없음)

> **2026-08-15 정정.** 처음엔 `AiPresentationResponseDto`가 원인이라고 적었으나 **틀렸습니다.**
> 그 DTO는 **아무 데서도 쓰이지 않는 죽은 코드**이고, 실제 저장 경로는 따로 있습니다.

`PresentationService.createAiProject()`는 응답을 **`Map`으로 직접 읽습니다.**

```
createAiProject(...) → Map
map.get("project_id")
  → instanceof Number 확인 (아니면 IllegalStateException)
  → ((Number) …).longValue()
  → Presentation.builder().aiProjectId(…)
```

`Number`로 받아 `longValue()`를 부르므로 Jackson이 `Integer`로 주든 `Long`으로 주든 **안전합니다.**
키 이름(`project_id`)도 위치(최상위)도 정확합니다. **여기는 고칠 것이 없습니다.**

**그럼 왜 null인가.** 이 저장 경로가 생기기 **전에 만들어진 옛 행**이기 때문입니다.
스프링 코드 자신이 그렇게 말하고 있습니다 — 예외 문구가 이미 들어 있습니다.

> *"이 발표에는 AI 프로젝트 번호가 없습니다. (aiProjectId 컬럼 도입 전에 만든 옛 데이터 —
> 발표 자료를 다시 업로드해주세요)"*

**조치: 발표 자료를 새로 업로드해서 확인해보세요.** 새 행에 값이 들어가면 정상입니다.
그래도 null이면 그때 다시 봐야 합니다(그 경우 `createAiProject`가 예외를 던졌을 테니
스프링 로그에 `IllegalStateException`이 남아 있을 겁니다).

> `AiPresentationResponseDto`는 쓰이지 않으므로 지우셔도 됩니다. 남겨두면 다음에 누군가
> "이게 파싱하는 줄" 알고 또 헛짚습니다(제가 그랬습니다).

## ⚠️ 2. 부분 녹음 — 이것 하나만 고치면 됩니다

`EvaluationService`가 AI 서버로 보내는 값은 **두 개뿐**입니다.

```
project_id, audio_file
```

그런데 컨트롤러는 `scriptId`를 받고 `Evaluation` 엔티티에는 `slideId`가 있습니다.
**즉 어느 슬라이드를 녹음했는지 스프링은 알고 있는데, AI 서버에 안 알려줍니다.**

슬라이드 하나만 녹음해도 AI 서버는 **발표 대본 전체**를 기준으로 채점합니다.
12장 중 3번 한 장만 읽으면 **나머지 11장이 전부 누락 처리**되어 완성도가 한 자릿수로
떨어집니다. 버그처럼 안 보이고 "AI가 이상한 것"처럼 보입니다.

**고치는 방법은 두 가지고, 둘 중 아무거나 하나면 됩니다.**

**(A) 조합한 대본을 보낸다** — 이미 하시려던 방식입니다. AI 서버가 이미 받고 있습니다.
```java
body.add("reference_text", 그_녹음이_읽은_대본);   // 부분 녹음이면 그 슬라이드 대본만
```
⚠️ **범위가 녹음과 같아야 합니다.** 한 장만 읽었는데 전체 대본을 넣으면 똑같이 망가집니다.
⚠️ 이어붙일 때 **`"Slide 1:"` 같은 라벨을 붙이지 마세요.** 라벨까지 '읽어야 할 말'로 채점됩니다.

**(B) 슬라이드 번호를 보낸다** — AI 서버가 저장된 대본에서 알아서 꺼냅니다.
```java
body.add("slide_number", slide.getSlideNumber());
```
⚠️ **`scriptId`를 그대로 넣으면 안 됩니다.** `slide_number`는 PPT의 몇 번째 장이냐이고
`scriptId`는 스프링 테이블의 PK입니다. 게다가 AI 서버의 `slide_number`는 **연속이 아닙니다** —
텍스트 없는 슬라이드(표지 등)는 저장하지 않기 때문입니다. 실제 데이터 예:

```
project 9 : slide_number = [1, 2, 3, 5, 6, 9, 10, 13, 14, 17, 18, 19]
```

없는 번호면 404, 잘못된 번호면 **엉뚱한 슬라이드와 비교**합니다.

> 전체 대본을 한 번에 녹음하는 흐름만 쓴다면 **지금 그대로도 맞습니다.**
> 화면이 슬라이드별 녹음을 제공하는지부터 확인하시면 됩니다.

## ❌ 3. 발표 습관 지표 — 급하지 않습니다

> 현재 우선순위(대본 생성 결과 → 하이라이팅 → 상세 피드백 → 다운로드)에 **습관 지표가
> 없습니다.** 화면에 안 쓸 거면 이 절은 건너뛰셔도 됩니다.

DB 컬럼은 있는데 받을 필드가 없습니다.

`Evaluation` 엔티티에는 이미 자리가 있습니다.

```java
private Integer fillerWordCount;
private String  fillerWordDetail;
private Float   pauseScore;
private String  pauseDetail;
```

그런데 `AiEvaluationResponseDto`에 `speech_metrics`를 받을 필드가 없어서
**이 컬럼들은 영원히 null입니다.** AI 서버는 이렇게 보냅니다.

```json
"speech_metrics": {
  "filler_count": 3,
  "filler_words": [{"word": "음", "count": 2}, {"word": "어", "count": 1}],
  "pause_count": 2,
  "pauses": [{"after_word": "그래서", "seconds": 1.8}],
  "speech_rate_wpm": 73
}
```

```java
@JsonProperty("speech_metrics")
private SpeechMetrics speechMetrics;

public static class SpeechMetrics {
    @JsonProperty("filler_count")    private Integer fillerCount;
    @JsonProperty("filler_words")    private List<Map<String,Object>> fillerWords;
    @JsonProperty("pause_count")     private Integer pauseCount;
    @JsonProperty("pauses")          private List<Map<String,Object>> pauses;
    @JsonProperty("speech_rate_wpm") private Integer speechRateWpm;
}
```

## ❌ 4. `highlights` / `deductions` — 상세 피드백 근거

DTO에 필드가 없어 버려집니다. 둘 다 **화면에 그대로 그리는 값**입니다.

```java
@JsonProperty("highlights") private Map<String,Object> highlights;
@JsonProperty("deductions") private Map<String,Object> deductions;
```

- `highlights.reference` → 원본 텍스트에 칠할 구간(누락)
- `highlights.recognized` → 인식 텍스트에 칠할 구간(추가)
- **빨간색은 `level: "error"`만.** `level: "warning"`(발음 부정확)은 *틀린 단어*가 아니라
  발음이 흐렸던 것이라, 빨강으로 칠하면 "대본을 잘못 읽었다"는 뜻이 됩니다.
- `deductions.factors[].message` → 상세 피드백 화면의 "왜 깎였는지" 문장

`highlights`를 안 받아도 `words_detail`로 직접 그릴 수 있습니다(위 ✅ 항목 참고).
`deductions`는 대체 경로가 없습니다.

---

## ⚠️ 5. `grades`는 곧 사라집니다 — 조치 불필요

총점 등급(A~F)을 없애고 **0~100 정수**만 보내도록 바꿨습니다.
`AiEvaluationResponseDto.grades`는 배포 후 **null**이 됩니다.

`Evaluation` 엔티티에 등급 컬럼이 없어(저장하는 곳이 없어) **터지지 않습니다.**
정리하실 때 `Grades` 클래스를 지우시면 됩니다.

점수 타입도 문제없습니다 — 엔티티가 `Float`라 정수 `87`이 `87.0f`로 들어갑니다.

## 참고 — AI 서버 쪽에서 이미 고친 것

- **평가 기준 대본에서 `"Slide N:"` 라벨 제거.** 라벨이 섞이면 Azure가 그것도 읽어야 할
  단어로 세서 없는 누락이 생기고, 결과 화면에 `"Slide 1"`이 빨갛게 칠해졌습니다.
- **`GET /api/projects/{id}`에 `full_script` 추가.** 슬라이드 대본을 순서대로 이어붙인
  전체 대본입니다. 프론트/스프링이 각자 합치면 라벨을 붙이거나 순서가 어긋나기 쉽고,
  그 텍스트가 `reference_text`로 되돌아오면 위 버그가 재현됩니다.
- **발음 평가 404 메시지에 진단 문구 추가.** 어떤 `project_id`를 받았고 어디서 가져와야
  하는지까지 응답 본문에 적습니다.
