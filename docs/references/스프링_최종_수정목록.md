# 2단계 — `PresentationService.java` 컴파일·주소 오류 4개

## 2-1. 주소 오타 (한 글자)

### 위치: `requestAndSaveHighlights()` → `restTemplate.postForEntity(` 첫 인자

```java
AI_BASE_URL + "/api/analytic/words",     // ← 이 줄을
AI_BASE_URL + "/api/analysis/words",     // ← 이렇게
```

`analytic` → **`analysis`**. 그런 주소가 없어서 404가 납니다. `pronunciation_highlights`
테이블이 계속 비어 있는 이유입니다.

## 2-2. `return` 누락

### 위치: `generateAiProjectIdForCustom()` → `try` 블록 마지막 줄

```java
    if (responseBody == null || !responseBody.containsKey("project_id")) {
        throw new IllegalStateException("...");
    }
    return ((Number) responseBody.get("project_id")).longValue();   // ← return 추가
```

## 2-3. 인자 타입 불일치

### 위치: `createPresentationForCustomScript()` → `scriptRepository.save(script);` 바로 다음 줄

```java
requestAndSaveHighlights(aiProjectId, script);                            // ← 이 줄을
requestAndSaveHighlights(aiProjectId, Map.of(slide.getSlideOrder(), script));  // ← 이렇게
```

메서드가 `Map<Integer, Script>`를 받습니다. **키는 `slideOrder`**입니다 — AI가 주는
`occurrences[].slide_number`로 해당 슬라이드의 대본을 찾아야 하이라이트를 어디에 매달지
정해지기 때문입니다.

## 2-4. 일반 발표는 하이라이팅을 아예 안 부릅니다

`requestAndSaveHighlights()`가 **커스텀 대본에서만** 불리고 있습니다.
파일 업로드 → 대본 생성으로 들어온 발표는 한 번도 안 부릅니다.

### 위치 ①: `callPythonAiServerForScript()` → 폴링 루프 안 → `saveScripts(...)` 다음 줄

```java
if ("completed".equals(status)) {
    saveScripts(presentation, statusBody);
    requestAndSaveHighlights(presentation.getAiProjectId(),
                             scriptsBySlideOrder(presentation));   // ← 추가
    isCompleted = true;
    break;
}
```

### 위치 ②: `PresentationService` 클래스 안, `saveScripts()` 아래에 새 메서드

```java
private Map<Integer, Script> scriptsBySlideOrder(Presentation presentation) {
    Map<Integer, Script> map = new HashMap<>();
    for (Slide slide : slideRepository.findByPresentation(presentation)) {
        slide.getScripts().stream()
                .max(Comparator.comparing(Script::getVersion))
                .ifPresent(s -> map.put(slide.getSlideOrder(), s));
    }
    return map;
}
```

**2-1 + 2-4가 하이라이팅을 살리는 최소 조합**입니다.

## 왜 base64인가

원래는 이미지마다 주소를 따로 두는 게 맞습니다(브라우저가 하루 캐시하고 응답도 가볍습니다).
그런데 **컨트롤러에 새 주소를 만들지 않기로** 해서, 이미지가 프론트까지 갈 통로가 상세 조회
응답밖에 없습니다. AI 서버에 `include_thumbnails` 옵션을 추가해 맞춰뒀습니다(2026-08-17 배포).

**컨트롤러는 한 글자도 안 고칩니다.** POST(대본 생성)와 GET 둘 다 이미
`getPresentationDetails()`를 부르고 있어서 두 경로에 자동으로 실립니다.

대가: 18장 기준 응답이 약 1MB 늘어나고 브라우저 캐시가 안 됩니다.

## 프론트

```jsx
{slide.thumbnailBase64
  ? <img src={`data:image/png;base64,${slide.thumbnailBase64}`} />
  : <PlaceholderBox number={slide.slideOrder} />}
```

| `thumbnailStatus` | 화면 |
|---|---|
| `pending` | 2초 뒤 GET 재조회 (18장 4초면 끝납니다) |
| `ready` | 이미지 표시 |
| `failed` / `unavailable` | 자리표시자 |
| `skipped` | 정상 — 대본만 올린 프로젝트 |

`pending`만 다시 물어보면 됩니다. 나머지 넷은 최종 상태입니다.

# 5단계 — `AudioService.java` (발음 듣기)

주소·파라미터·응답이 **전부** 다릅니다.

```
현재: POST /api/tts/synthesize   body { text, voice_style, speed }
      응답에서 audio_url, duration 을 꺼내는 중   ← 그런 필드가 없습니다
```

**응답은 JSON이 아니라 MP3 바이트입니다.**

### 위치: `AudioService` 클래스 → TTS 호출 메서드 전체 교체

```java
public byte[] synthesizeWord(Long presentationId, String word, String voice, Integer speed) {
    Presentation p = presentationRepository.findById(presentationId)
            .orElseThrow(() -> new IllegalArgumentException("존재하지 않는 발표 자료입니다."));

    if (word == null || word.isBlank()) {
        throw new IllegalArgumentException("음성으로 변환할 단어가 없습니다.");
    }

    RestTemplate restTemplate = new RestTemplate();
    SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
    factory.setConnectTimeout(10_000);
    factory.setReadTimeout(30_000);
    restTemplate.setRequestFactory(factory);

    HttpHeaders headers = new HttpHeaders();
    headers.setContentType(MediaType.APPLICATION_JSON);
    addApiKeyHeader(headers);

    Map<String, Object> body = new HashMap<>();
    body.put("word", word);
    body.put("project_id", p.getAiProjectId());   // 저장된 발음기호를 찾아 쓴다 (더 정확)
    if (voice != null && !voice.isBlank()) body.put("voice", voice);
    if (speed != null) body.put("speed", speed);

    try {
        ResponseEntity<byte[]> res = restTemplate.postForEntity(
                AI_BASE_URL + "/api/tts/word",        // ⚠️ /api/tts/synthesize 아님
                new HttpEntity<>(body, headers),
                byte[].class);
        return res.getBody();
    } catch (HttpStatusCodeException e) {
        throw new ResponseStatusException(e.getStatusCode(),
                "AI 음성 합성 실패: " + extractDetail(e.getResponseBodyAsString()));
    }
}
```

**단어 하나만 읽어줍니다.** 전체 대본 듣기 API는 없습니다 — Clova Voice가 한국어 음운
규칙을 일부만 적용해서(`각자`→[각자], `책임`→[책임]), 철자를 그대로 넣으면 **틀린 발음이
나갑니다.** 그래서 서버가 G2P로 만든 발음 문자열을 단어마다 넣습니다.

화자는 **동현·대성·혜리·고은 4명**, 속도는 **-5 ~ +5**(음수가 빠름)입니다.
목록은 `GET /api/tts/voices`로 받으시면 프론트가 하드코딩하지 않아도 됩니다.
