### 위치 ①: `slideScripts` 만드는 `.map(slide -> {...})` 안 → `.version(...)` 다음 줄


```java
        .hasFile(hasFile)
        .thumbnailStatus(thumbnailStatus)          // ← 추가
        .build();
```

DTO 필드는 이미 있으므로 이 3줄이 전부입니다.

### 프론트 표시 규칙

```jsx
{slide.thumbnailBase64
  ? <img src={`data:image/png;base64,${slide.thumbnailBase64}`} />
  : <PlaceholderBox number={slide.slideOrder} />}
```

| `thumbnailStatus` | 화면 |
|---|---|
| `pending` | 2초 뒤 GET 재조회 |
| `ready` | 이미지 표시 |
| `failed` / `unavailable` | 자리표시자 |
| `skipped` | 정상 — 대본만 올린 프로젝트 |

⚠️ **try/catch 필수** — 현재 `requestAndSaveHighlights()`는 실패 시 예외를 던지는데,
여기서 안 잡으면 대본이 다 만들어지고도 마지막에 통째로 실패합니다.
같은 이유로 `createPresentationForCustomScript()`의 기존 호출부도 try/catch로 감싸는 걸
권합니다 (지금은 AI 단어 분석이 실패하면 커스텀 대본 등록 전체가 롤백됩니다).

### 위치 ②: 같은 클래스에 새 private 메서드

```java
private Map<Integer, Script> scriptsBySlideOrder(Presentation presentation) {
    Map<Integer, Script> map = new HashMap<>();
    for (Slide slide : this.slideRepository.findByPresentation(presentation)) {
        slide.getScripts().stream()
                .max(Comparator.comparing(Script::getVersion))
                .ifPresent(s -> map.put(slide.getSlideOrder(), s));
    }
    return map;
}
```

## 4. AudioController 경로 버그 — 주소가 이중으로 붙었습니다

클래스에 `@RequestMapping("/api/audio")`가 남아 있어서 실제 주소가
**`/api/audio/api/presentations/{id}/tts/word`** 가 됐습니다.

### 위치: `AudioController` 클래스 선언부 → `@RequestMapping` 줄 삭제

```java
@RestController
// @RequestMapping("/api/audio")   ← 이 줄을 지우면
public class AudioController {
    @PostMapping("/api/presentations/{presentationId}/tts/word")   // 이 주소가 그대로 최종 주소
```

프론트는 아직 TTS를 안 붙였으므로(배포 번들 확인) 지금 고치는 게 안전합니다.
요청/응답 계약: body `{ word, voice?, speed? }` → 응답 `audio/mpeg` MP3 바이트.
프론트는 blob으로 받아 `URL.createObjectURL(blob)`로 재생. 화자 목록은
`GET /api/tts/voices`(AI 직접 아님, 스프링 경유 시 프록시 필요 없음 — 하드코딩해도 4명:
동현·대성·혜리·고은, 속도 -5~+5).

### 위치: `evaluateVoice()` → `evaluationRepository.save(evaluation)` 다음

```java
if (savedEvaluation.getAiEvaluationId() != null) {
```
