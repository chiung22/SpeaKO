# 2단계 — 일반 발표(PPT 업로드)도 하이라이팅 (10분)

지금 `requestAndSaveHighlights()`는 **커스텀 대본에서만** 불립니다. PPT로 만든 발표는
발음 주의 단어가 한 번도 저장되지 않아 대본 화면 하이라이팅이 빈 채로 나갑니다.

### 파일: 같은 `PresentationService.java`

## 2-1. 대본 생성 완료 시 호출 추가

### 메서드: `callPythonAiServerForScript(...)` → 폴링 for 루프 안

**[지금 코드]**:

```java
if ("completed".equalsIgnoreCase(status)) {
    saveScripts(presentation, statusBody);
    isCompleted = true;
    break;
}
```

**[바꾼 코드]**:

```java
if ("completed".equalsIgnoreCase(status)) {
    saveScripts(presentation, statusBody);
    try {
        requestAndSaveHighlights(presentation.getAiProjectId(),
                                 scriptsBySlideOrder(presentation));
    } catch (Exception e) {
        // 하이라이팅 실패가 대본 생성 전체를 죽이면 안 된다
        System.err.println("하이라이팅 수신 실패(생성은 계속): " + e.getMessage());
    }
    isCompleted = true;
    break;
}
```

⚠️ **try/catch를 빼먹으면 안 됩니다** — `requestAndSaveHighlights()`가 실패 시 예외를
던지게 돼 있어서, 안 잡으면 대본이 다 만들어지고도 마지막에 통째로 실패합니다.

## 2-2. 새 private 메서드 추가

### 위치: 같은 클래스 안, `saveScripts()` 메서드 바로 아래에 통째로 추가

```java
private Map<Integer, Script> scriptsBySlideOrder(Presentation presentation) {
    Map<Integer, Script> map = new HashMap<>();
    for (Slide slide : slideRepository.findByPresentation(presentation)) {
        slide.getScripts().stream()
                .max(Comparator.comparing(Script::getVersion))
                .ifPresent(s -> map.put(slide.getSlideOrder(), s));
    }
    return map;
}
```

(`Map`/`HashMap`/`Comparator` import는 이 파일에 이미 있습니다.)

## 2-3. 커스텀 대본 호출부도 try/catch (안전장치)

### 메서드: `createPresentationForCustomScript(...)` 맨 아래쪽

**[지금 코드]**:

```java

```

**[바꾼 코드]**:


# 3단계 — 재생성 FK 보호 (5분) ⚠️ 안 하면 재생성이 깨집니다

`pronunciation_highlights`가 `scripts`를 FK로 참조합니다. 커스텀 대본은 이미 하이라이트를
저장하므로, **그 발표를 전체 재생성하면 대본 삭제가 FK 제약으로 실패해 500**이 납니다.
2단계를 넣으면 일반 발표도 같은 위험이 생깁니다.

### 파일: 같은 `PresentationService.java`

## 3-1. 전체 재생성 (필수)

### 메서드: `regenerateAll(...)`

**[지금 코드]** — 슬라이드 삭제 시작 부분:

```java
List<Slide> old = slideRepository.findByPresentation(presentation);
for (Slide s : old) {
    scriptRepository.deleteBySlide(s);
}
slideRepository.deleteAll(old);
```

**[바꾼 코드]** — 맨 앞에 하이라이트 삭제 1문장:

```java
// 대본을 지우기 전에, 대본을 참조하는 하이라이트부터 지운다 (FK)
pronunciationHighlightRepository.deleteAll(
        pronunciationHighlightRepository.findByPresentationId(presentationId));

List<Slide> old = slideRepository.findByPresentation(presentation);
for (Slide s : old) {
    scriptRepository.deleteBySlide(s);
}
slideRepository.deleteAll(old);
```

(`findByPresentationId`는 리포지토리에 이미 있습니다. 새 하이라이트는 재생성 완료 시
2-1이 자동으로 다시 만듭니다.)

## 3-2. 부분 재생성 (권장)

부분 재생성은 대본 **내용만** 바뀌므로 FK 문제는 없지만, 저장된 하이라이트 좌표가
옛 대본 기준이라 **틀린 자리를 칠하게 됩니다.**

### 메서드: `regenerateOne(...)`

**[지금 코드]** — 맨 끝:

```java
script.updateContent(String.valueOf(data.get("script")));
scriptRepository.save(script);
return getPresentationDetails(presentationId);
```

**[바꾼 코드]**:

```java
script.updateContent(String.valueOf(data.get("script")));
scriptRepository.save(script);

// 이 대본의 옛 하이라이트를 지우고, 바뀐 내용 기준으로 다시 받는다
List<PronunciationHighlight> stale = pronunciationHighlightRepository
        .findByPresentationId(presentationId).stream()
        .filter(h -> h.getScript().getScriptId().equals(scriptId))
        .toList();
pronunciationHighlightRepository.deleteAll(stale);
try {
    requestAndSaveHighlights(presentation.getAiProjectId(),
            Map.of(script.getSlide().getSlideOrder(), script));
} catch (Exception e) {
    System.err.println("하이라이팅 갱신 실패(재생성은 계속): " + e.getMessage());
}

return getPresentationDetails(presentationId);
```

# 5단계 — 상세 피드백 저장 (10분)

`ai_evaluation_id` 저장까지는 해두셨으니 피드백 호출만 남았습니다. 지금은
`feedback_detail` 컬럼이 항상 NULL입니다.

### 파일: `src/main/java/com/example/speako/domain/evaluation/service/EvaluationService.java`
### 메서드: `evaluateVoice(...)`

**[지금 코드]** — 평가 저장 직후:

```java
Evaluation savedEvaluation = evaluationRepository.save(evaluation);
return EvaluationResponseDTO.ResultDTO.builder()
```

**[바꾼 코드]** — save와 return **사이**에 블록 삽입:

```java
Evaluation savedEvaluation = evaluationRepository.save(evaluation);

// AI 상세 피드백(총평/잘한 점/개선점/연습 팁)을 받아서 저장한다.
// 실패해도 평가 결과 반환은 막지 않는다.
if (savedEvaluation.getAiEvaluationId() != null) {
    try {
        HttpHeaders fbHeaders = new HttpHeaders();
        addApiKeyHeader(fbHeaders);
        ResponseEntity<Map> fb = restTemplate.postForEntity(
                AI_BASE_URL + "/api/evaluation/" + savedEvaluation.getAiEvaluationId() + "/feedback",
                new HttpEntity<>(fbHeaders), Map.class);
        Map fbBody = fb.getBody();
        if (fbBody != null && fbBody.get("data") != null) {
            savedEvaluation.updateFeedbackDetail(
                    objectMapper.writeValueAsString(fbBody.get("data")));
            evaluationRepository.save(savedEvaluation);
        }
    } catch (Exception e) {
        System.err.println("상세 피드백 수신 실패: " + e.getMessage());
    }
}

return EvaluationResponseDTO.ResultDTO.builder()
```

맞춰둔 것들이라 그대로 컴파일됩니다:
- `restTemplate` — 같은 메서드 위에서 만든 변수 재사용 (읽기 타임아웃 600초라 충분)
- `updateFeedbackDetail(String)` — `Evaluation` 엔티티에 **이미 만들어 두신 메서드**
- `objectMapper`, `addApiKeyHeader` — 이 클래스에 이미 있음

AI 쪽은 같은 평가에 두 번 부르면 캐시를 돌려주므로(HCX 재과금 없음) 재시도해도 안전합니다.

프론트에 피드백을 노출하려면 `ResultDTO`에 `feedbackDetail` 필드 하나 추가하고 빌더에
`.feedbackDetail(savedEvaluation.getFeedbackDetail())`을 넣으면 됩니다 — 필드 추가라
기존 연동에는 영향 없습니다.

# 사소 (시간 남으면)

## slideCount가 항상 1로 저장됨

### 파일: `PresentationService.java` → 메서드: `extractSlideCount(...)`

지금 `slide_count` 키를 찾는데 AI 응답에 그 키가 없습니다. AI 응답의 실제 구조는
`data.slides` **리스트**이므로 그 크기를 세야 합니다:

```java
private int extractSlideCount(Map<String, Object> aiResponse) {
    try {
        Object data = aiResponse.get("data");
        if (data instanceof Map) {
            Object slides = ((Map<?, ?>) data).get("slides");
            if (slides instanceof List) {
                return ((List<?>) slides).size();
            }
        }
        return 1;
    } catch (Exception e) {
        return 1;
    }
}
```

(화면 응답에는 안 나가는 DB 값이라 시연에는 지장 없습니다.)

## `@Transactional` + 폴링 — 데모 뒤에

대본 생성 30여 초 동안 MySQL 커넥션을 쥐고 있는 구조입니다. 시연은 한 명씩이라
안 터지지만, 실사용자를 받기 전에 손봐야 합니다.
