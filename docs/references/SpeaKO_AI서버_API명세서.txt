================================================================================
                  SpeaKO AI 서버 API 명세서 (프론트엔드 연동용)
================================================================================

  작성 기준 : AI 서버(FastAPI) main 브랜치
  엔드포인트 : 총 15개
  문의       : AI 서버 담당

--------------------------------------------------------------------------------
[0] 공통 사항
--------------------------------------------------------------------------------

  Base URL
    로컬   : http://localhost:8000
    배포   : (배포 주소)

  인증
    서버에 SPEAKO_API_KEY가 설정돼 있으면 모든 /api/* 요청에 헤더 필요
      X-API-Key: <발급받은 키>
    설정 안 돼 있으면 인증 없이 호출 가능 (로컬 개발용)

  CORS
    프론트 도메인이 서버 허용 목록에 있어야 브라우저가 응답을 받습니다.
    기본 허용: http://localhost:3000, http://localhost:5173,
              https://speakofront.vercel.app, 그리고 모든 *.vercel.app
    도메인이 바뀌면 서버 환경변수(CORS_ALLOW_ORIGINS) 수정 필요 -> AI 서버 담당에게 요청

  실패 응답 규약 (공통)
    422  입력값이 잘못됨 (필수값 누락, 허용 안 되는 파일 형식/스타일 값 등)
    404  대상을 찾을 수 없음 (project_id, slide_number, job_id, evaluation_id)
    413  업로드 파일이 너무 큼
    502  외부 AI 호출 실패 (HCX / Azure)
    실패 시 본문: { "detail": "사람이 읽을 수 있는 메시지" }

  업로드 제한
    발표 자료 : 20MB,  .pptx / .pdf     (※ 구버전 .ppt 는 지원 안 함)
    코칭용 대본: 20MB,  .docx / .txt / .pdf
    녹음 파일 : 10MB,  .webm / .wav / .mp3 / .m4a


--------------------------------------------------------------------------------
[1] 전체 흐름 요약
--------------------------------------------------------------------------------

  ● AI 대본 생성
     1. POST   /api/projects                        자료 업로드 -> project_id
     2. POST   /api/script/full                     생성 시작   -> job_id (즉시 응답)
     3. GET    /api/script/jobs/{job_id}            1~2초마다 폴링 -> 완료되면 대본
     4. PUT    /api/projects/{id}/slides/{n}        사용자가 고친 대본 저장
        POST   /api/projects/{id}/slides            슬라이드 추가
        DELETE /api/projects/{id}/slides/{n}        슬라이드 삭제
        POST   /api/script/partial                  슬라이드 하나만 다시 생성

  ● 발표 발음 코칭
     5. POST   /api/analysis/words                  발음 주의 단어 + 발음기호
     6. POST   /api/evaluation/audio                녹음 업로드 -> 점수 + 인식 텍스트
     7. POST   /api/evaluation/{id}/feedback        AI 코칭 피드백

  ● 마이페이지
     8. GET    /api/projects                        대본 생성 기록
        GET    /api/evaluations                     발표 코칭 내역
        GET    /api/projects/{id}                   상세 (대본/단어/평가 전부)
        DELETE /api/projects/{id}                   기록 삭제


================================================================================
[2] 프로젝트 생성
================================================================================

  POST /api/projects
  Content-Type: multipart/form-data

  ● 입력 방식 3가지 중 하나를 사용합니다.

    (1) PPT/PDF 업로드            - 화면: AI 대본 생성 (PPT 있음)
        file          : .pptx 또는 .pdf   (필수)
        topic         : 발표 주제          (권장 - 대본 품질에 직접 반영됨)
        project_name  : 프로젝트 이름      (선택)

    (2) 자료 없이 주제만           - 화면: AI 대본 생성 (PPT 없음)
        topic         : 발표 주제          (필수)
        outline       : 목차/가이드라인    (필수)
        project_name  : 프로젝트 이름      (선택)

    (3) 완성된 대본으로 시작       - 화면: 발표 발음 코칭
        script_text   : 대본 전문 붙여넣기 (필수)
        또는
        mode          : "coaching"
        file          : .docx / .txt / .pdf

  ● 응답 (200)
    {
      "success": true,
      "project_id": 12,
      "data": {
        "metadata": { "topic": "발표 주제", "keywords": [] },
        "slides": [
          { "slide_number": 1, "content": "슬라이드에서 추출된 원문" }
        ]
      }
    }

  ● 참고
    - 텍스트가 없는 이미지 슬라이드는 AI 비전이 읽어서 자동 인식합니다.
    - 텍스트도 이미지도 없는 빈 슬라이드는 결과에서 빠질 수 있습니다(정상).


================================================================================
[3] 대본 생성 (★ 비동기 - 중요)
================================================================================

  대본 생성은 20~30초가 걸립니다. 요청을 붙잡고 기다리면 타임아웃으로 끊기므로,
  "접수번호(job_id)를 먼저 받고 -> 상태를 물어보는" 방식입니다.

--------------------------------------------------------------------------------
 3-1) 생성 시작
--------------------------------------------------------------------------------

  POST /api/script/full
  Content-Type: application/json

  ● 요청
    {
      "project_id": 12,               // 필수
      "presentation_time": 8,         // 필수, 분 단위
      "style": "격식체",               // 필수, "격식체" | "편안한 말투"  (다른 값은 422)
      "topic": "발표 주제",            // 선택, 비우면 프로젝트에 저장된 주제 사용
      "audience": "교수님",            // 선택, 예) 교수님 / 면접관 / 초등학생
      "extra_requirement": ""         // 선택, 추가 가이드라인 자유 입력
    }

  ● 응답 (202) - 기다리지 않고 즉시 옵니다
    {
      "success": true,
      "job_id": "9f2c8a1b...",
      "status": "processing"
    }

--------------------------------------------------------------------------------
 3-2) 진행 상태 폴링
--------------------------------------------------------------------------------

  GET /api/script/jobs/{job_id}

  1~2초 간격으로 호출하면서 로딩 스피너를 돌립니다.

  ● 처리 중
    { "success": true, "job_id": "9f2c8a1b", "status": "processing" }

  ● 완료
    {
      "success": true,
      "job_id": "9f2c8a1b",
      "status": "completed",
      "project_id": 12,
      "data": {
        "slides": [
          { "slide_number": "1", "script": "안녕하십니까. 이번 ..." },
          { "slide_number": "2", "script": "다음으로 ..." }
        ],
        "missing_slide_numbers": [],       // 끝내 생성하지 못한 슬라이드 번호
        "thin_source_slide_numbers": []    // 원문이 제목 한 줄뿐이라 근거 없이 쓴 슬라이드 번호
      }
    }

  ● 실패
    {
      "success": true, "job_id": "9f2c8a1b",
      "status": "failed",
      "error": "대본 생성에 실패했습니다."
    }

  ● 프론트 처리 순서
    1. status 가 "processing" 이면 계속 폴링
    2. "completed" -> data.slides 로 결과 렌더, 스피너 종료
    3. "failed"    -> error 메시지 표시 + 다시 시도 버튼
    4. 404 응답    -> 작업 정보가 사라진 상태. "다시 시도해 주세요" 안내
                     (서버가 재시작되면 진행 중이던 작업은 사라집니다)

  ● 주의
    - slide_number 가 문자열("1")로 옵니다. 숫자 비교 시 형변환 필요.
    - missing_slide_numbers 에 번호가 들어 있으면 그 슬라이드는 대본이 비어 있습니다.
      (모델이 끝내 형식을 못 지킨 경우) 화면에서 "이 슬라이드는 다시 생성해 주세요"로
      안내하고, POST /api/script/partial 로 그 장만 다시 만들 수 있습니다.
    - thin_source_slide_numbers 에 번호가 들어 있으면 그 슬라이드는 PPT에서 읽은 내용이
      제목 한 줄뿐이라 대본의 근거가 없었던 장입니다. 대본은 있지만 슬라이드를 가리키는
      일반적인 안내문이므로, "내용을 직접 확인·보완해 주세요" 배지를 띄워 주세요.
      근거가 없어서 지어내지 않은 것이므로, 재생성해도 결과는 같습니다.
      (그냥 그럴듯하게 지어내면 발표자가 그대로 읽다가 사실이 아닌 말을 하게 됩니다)
    - 슬라이드 수만큼 AI 호출이 병렬로 나가므로, 장수가 많으면 시간이 더 걸립니다.

[4] 대본 편집 (결과 화면)
================================================================================

--------------------------------------------------------------------------------
 4-1) 고친 대본 저장
--------------------------------------------------------------------------------

  PUT /api/projects/{project_id}/slides/{slide_number}
  Content-Type: application/json

  ● 요청
    { "script": "사용자가 직접 고친 대본" }
      // source_content 를 같이 보내면 원문도 수정됩니다 (선택)
      // 빈 문자열("")도 허용 - 내용을 비우는 것도 편집으로 봅니다

  ● 응답
    { "success": true, "project_id": 12,
      "data": { "slides": [ { "slide_number": 1,
                              "source_content": "...", "script": "..." } ] } }

  ● 참고
    - PPT 없이 만든 프로젝트(전체 대본 한 덩어리)는 slide_number = 1 로 저장하면 됩니다.

--------------------------------------------------------------------------------
 4-2) 슬라이드 추가
--------------------------------------------------------------------------------

  POST /api/projects/{project_id}/slides
  Content-Type: application/json

  ● 요청
    { "position": 2,          // 선택. 이 자리에 끼워넣고 뒤 번호를 밀어냄
                              //       없으면 맨 끝에 추가
      "script": "",           // 선택
      "source_content": "" }  // 선택

  ● 응답
    { "success": true, "project_id": 12, "added_slide_number": 2,
      "data": { "slides": [ ... 재정렬된 전체 목록 ... ] } }

--------------------------------------------------------------------------------
 4-3) 슬라이드 삭제
--------------------------------------------------------------------------------

  DELETE /api/projects/{project_id}/slides/{slide_number}

  ● 응답
    { "success": true, "project_id": 12,
      "data": { "slides": [ ... 재정렬된 전체 목록 ... ] } }

  ● 참고
    - 추가/삭제 후 슬라이드 번호는 1..N 으로 자동 재정렬됩니다.
    - 마지막 남은 한 장은 삭제할 수 없습니다 (422).
    - 세 API 모두 응답에 "정리된 전체 목록"이 오므로, 그대로 화면을 다시 그리면 됩니다.

--------------------------------------------------------------------------------
 4-4) 슬라이드 부분 재생성
--------------------------------------------------------------------------------

  POST /api/script/partial
  Content-Type: application/json

  ● 요청
    {
      "project_id": 12,
      "target_slide": 3,              // 다시 만들 슬라이드 번호
      "style": "격식체",               // 필수, "격식체" | "편안한 말투"
      "audience": "면접관",            // 선택
      "extra_requirement": "더 짧게"   // 선택
    }

  ● 응답
    { "success": true, "project_id": 12,
      "data": { "slide_number": "3", "script": "다시 생성된 대본" } }

  ● 참고
    - 기존 대본을 다시 보낼 필요 없습니다. 서버에 저장된 것을 사용합니다.
    - 이건 동기 호출입니다(몇 초). 폴링 불필요.

[5] 발음 주의 단어 (하이라이팅용)
================================================================================

  POST /api/analysis/words
  Content-Type: application/json

  ● 요청
    { "project_id": 12 }

  ● 응답
    {
      "success": true, "project_id": 12,
      "data": {
        "words": [
          { "word": "발전", "phoneme": ["발쩐"], "category": "표기-발음불일치" },
          { "word": "준비", "phoneme": ["준비"], "category": "장단음" }
        ],
        "summary": { "장단음": 6, "연음": 1, "표기-발음불일치": 3 }
      }
    }

  ● category 값
    "장단음"            소리 길이를 구분해야 하는 단어
    "연음"              앞 글자 받침이 뒤로 넘어가 발음되는 단어
    "표기-발음불일치"    쓰는 것과 읽는 것이 다른 단어
    null                철자와 발음이 같음 (하이라이팅 대상 아님)

  ● 참고
    - 하이라이트 범례와 요약 개수는 summary 를 그대로 쓰면 됩니다.
    - phoneme 은 배열입니다. 화면에는 [발쩐] 형태로 표기하면 됩니다.

[6] 녹음 발음 평가
================================================================================

  POST /api/evaluation/audio
  Content-Type: multipart/form-data

  ● 요청
    project_id      : 12                    (필수)
    audio_file      : 녹음 파일              (필수) .webm/.wav/.mp3/.m4a, 최대 10MB
    slide_number    : 3                     (선택) 슬라이드별로 나눠 녹음할 때
    reference_text  : 평가 기준 텍스트        (선택)

    ※ 평가 기준이 되는 대본은 아래 순서로 정해집니다.
       1) reference_text 를 주면 그것
       2) slide_number 를 주면 그 슬라이드 대본만  <- 슬라이드별 부분 녹음
       3) 둘 다 없으면 대본 전체
       슬라이드 하나만 읽었는데 전체 대본을 기준으로 채점하면 완성도가 바닥으로
       나오므로, 부분 녹음일 때는 slide_number 를 꼭 넣어주세요.

  ● 응답
    {
      "success": true,
      "project_id": 12,
      "evaluation_id": 5,
      "slide_number": 3,              // 슬라이드별 녹음이면 그 번호, 전체 녹음이면 null
      "overall_scores": {
        "accuracy": 87.4,             // 정확도
        "fluency": 82.1,              // 유창성
        "completeness": 95.0,         // 완성도
        "pronunciation_score": 84.3   // 종합 발음 점수 (화면의 "총점"에 사용)
      },
      "recognized_text": "AI가 실제로 인식한 문장",
      "words_detail": [
        { "word": "발전", "accuracy_score": 52.0, "error_type": "Mispronunciation" }
      ]
    }

  ● error_type 값
    "None"              정상적으로 읽음
    "Mispronunciation"  잘못 발음함
    "Omission"          읽지 않고 건너뜀

  ● 참고
    - 점수는 소수점 1자리(0~100)로 옵니다. 그대로 표시하면 됩니다. (0~5점 아님)
    - recognized_text 와 원본 대본을 좌우로 놓으면 "원본 <-> 인식 텍스트" 비교 화면이 됩니다.
    - 녹음 도중에 멈춰도 읽은 부분까지만 채점됩니다. 어디까지 읽었는지 알려줄 필요 없습니다.
    - 슬라이드별로 녹음하면 slide_number 가 결과에 저장되어, 코칭 내역에서
      "3번 슬라이드 87점"처럼 구분해서 보여줄 수 있습니다.
    - 없는 슬라이드 번호는 404, 아직 대본이 없는 슬라이드는 422 로 응답합니다.
    - 브라우저 녹음 파일(webm)을 그대로 올리면 서버가 변환해서 처리합니다.

[7] AI 코칭 피드백
================================================================================

  POST /api/evaluation/{evaluation_id}/feedback
  (요청 본문 없음)

  ● 응답
    {
      "success": true,
      "evaluation_id": 5,
      "cached": false,
      "data": {
        "summary": "전반적으로 또렷하게 발음했습니다. 다만 받침 처리가 아쉽습니다.",
        "strengths":     [ "'평가'를 정확하게 발음하셨습니다." ],
        "improvements":  [ "'발전'의 받침을 끝까지 발음하세요." ],
        "practice_tips": [ "거울을 보며 입 모양을 확인해 보세요.",
                           "녹음해서 다시 들어보세요." ],
        "weak_words": [
          { "word": "발전", "accuracy_score": 52.0, "error_type": "Mispronunciation" }
        ]
      }
    }

  ● 참고
    - 생성에 몇 초 걸립니다. 스피너를 띄워주세요.
    - 이미 만들어진 피드백이 있으면 다시 만들지 않고 그대로 돌려줍니다 (cached: true).
      여러 번 눌러도 비용이 늘지 않습니다.
    - weak_words 는 지적의 근거가 된 단어입니다. 함께 표시하면 이해가 쉽습니다.
    - evaluation_id 는 [6] 녹음 평가 응답에서 받은 값입니다.

[8] 마이페이지 / 기록
================================================================================

--------------------------------------------------------------------------------
 8-1) 대본 생성 기록
--------------------------------------------------------------------------------

  GET /api/projects

    { "success": true,
      "data": [ { "id": 12, "name": "프로젝트명", "topic": "발표 주제",
                  "slide_count": 8, "created_at": "2026-08-04T10:00:00" } ] }

--------------------------------------------------------------------------------
 8-2) 발표 코칭 내역
--------------------------------------------------------------------------------

  GET /api/evaluations      (프로젝트 구분 없이 최신순)

    { "success": true,
      "data": [ { "id": 5, "project_id": 12, "project_name": "프로젝트명",
                  "slide_number": 3 또는 null,
                  "accuracy_score": 87.4, "fluency_score": 82.1,
                  "completeness_score": 95.0, "pronunciation_score": 84.3,
                  "feedback": { ... } 또는 null,

[9] 권장 연동 순서
================================================================================

  [AI 대본 생성 화면]
    1. 파일/주제 입력  -> POST /api/projects            -> project_id 저장
    2. "생성하기" 클릭 -> POST /api/script/full          -> job_id 저장, 스피너 ON
    3. 1~2초마다        -> GET  /api/script/jobs/{job_id}
    4. completed       -> data.slides 렌더, 스피너 OFF
    5. 사용자 편집     -> PUT/POST/DELETE .../slides
       특정 장 재생성  -> POST /api/script/partial

  [발음 코칭 화면]
    6. 대본 확정 후    -> POST /api/analysis/words       -> 하이라이팅 + 요약
    7. 녹음 완료       -> POST /api/evaluation/audio     -> 점수 + 인식 텍스트
                          (evaluation_id 저장)
    8. 피드백 보기     -> POST /api/evaluation/{id}/feedback

  [마이페이지]
    9. GET /api/projects, GET /api/evaluations, DELETE /api/projects/{id}

[10] 아직 제공하지 않는 것 (프론트 참고)
================================================================================

  - 슬라이드 미리보기 썸네일
      서버는 PPT에서 텍스트만 추출합니다. 슬라이드를 이미지로 렌더링해 주지 않습니다.

      서버 내부 구현은 되어 있으나 엔드포인트가 아직 연결되지 않았습니다.
      연결되면 별도 안내드리겠습니다.

  - 사용자 계정 / 로그인 / 요금제
      AI 서버 담당이 아닙니다. 스프링 백엔드에 문의해 주세요.
