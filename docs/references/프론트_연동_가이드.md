# 프론트 연동 가이드 — 복붙용 코드 전체

> 2026-08-18 밤 기준. **배포된 스프링 JAR을 디컴파일해 파라미터 이름까지 실제 값으로 확인**했고,
> 코드는 전부 지금 서버에 그대로 동작하는 형태입니다.
> 백엔드 주소: `http://13.209.87.115:8080` (HTTPS 아님 — 아래 Mixed Content 참고)

---

## 0. 공통 준비

```js
// api.js
const BASE = "http://13.209.87.115:8080";

function authHeaders() {
  return { Authorization: `Bearer ${localStorage.getItem("accessToken")}` };
}

/** 모든 응답은 { code, message, result, success } 래퍼입니다. 데이터는 result 안에 있습니다. */
async function unwrap(res) {
  const body = await res.json();
  if (!body.success) throw new Error(body.message || "요청 실패");
  return body.result;          // ⚠️ data가 아니라 result
}
```

### ⚠️ 시연 PC마다 1회 — Mixed Content 예외

HTTPS 프론트에서 HTTP 백엔드를 부르므로 브라우저가 기본 차단합니다.
`chrome://settings/content/insecureContent` → 허용 목록에 `https://speakofront.vercel.app` 추가.
(요청이 아예 안 나가는데 에러도 안 보이면 십중팔구 이겁니다 — Network 탭에 `(blocked:mixed-content)`)

### ⚠️ ID 3종 구분 — 오늘 다운로드가 실패한 원인

| ID | 어디서 나옴 | 용도 |
|---|---|---|
| **`presentationId`** | 생성·조회 응답 `result.presentationId` | **모든 API 경로에 쓰는 것** |
| `slideId` / `scriptId` | `result.slides[]` 안 | 부분 재생성에만 |
| AI `project_id` (110, 112…) | 백엔드 내부 번호 | ❌ 프론트가 쓸 일 없음 |

오늘 `GET /api/presentations/12/download/...`가 17번 실패했는데, **12는 존재하지 않는
발표입니다.** 다운로드·하이라이트·평가 전부 생성 응답의 `presentationId`를 그대로 쓰세요.

## 1. 발표 생성 (PPT 업로드 / 주제만)

```js
/** PPT 업로드 + 대본 생성. 완료까지 30~100초 걸리므로 로딩 UI 필수. */
async function createPresentation({ file, topic, duration, tone, guideline }) {
  const form = new FormData();
  if (file) form.append("file", file);
  form.append("request", new Blob([JSON.stringify({ topic, duration, tone, guideline })],
                                  { type: "application/json" }));

  const res = await fetch(`${BASE}/api/presentations`, {
    method: "POST", headers: authHeaders(), body: form,
  });
  const created = await unwrap(res);

  // ⚠️ 알려진 버그: 생성 직후 응답의 slides가 빈 배열로 올 수 있습니다.
  //    (백엔드 JPA 캐시 문제 — 수정 대기 중) 한 번 더 조회해서 그 값을 쓰세요.
  return getPresentation(created.presentationId);
}

/** 상세 조회 — 대본·썸네일이 모두 이 응답에 있습니다. */
async function getPresentation(presentationId) {
  const res = await fetch(`${BASE}/api/presentations/${presentationId}`,
                          { headers: authHeaders() });
  return unwrap(res);
  // result = { presentationId, topic, duration, tone, fileUrl, hasFile,
  //            thumbnailStatus,        // pending | ready | failed | unavailable | skipped
  //            slides: [ { slideId, slideOrder, slideTitle, rawText,
  //                        scriptId, content, version,
  //                        hasThumbnail, thumbnailBase64 } ] }   // base64는 null일 수 있음
}
```

### 슬라이드 미리보기(썸네일) 렌더

이미지 URL이 따로 없습니다. **base64가 상세 응답에 실려 옵니다.**

```jsx
{slides.map((s) =>
  s.thumbnailBase64
    ? <img key={s.slideOrder} alt={`슬라이드 ${s.slideOrder}`}
           src={`data:image/png;base64,${s.thumbnailBase64}`} />
    : <div key={s.slideOrder} className="thumb-placeholder">{s.slideOrder}</div>
)}
```

`thumbnailStatus`가 `pending`이면 2초 뒤 `getPresentation`을 다시 부르세요 (18장 기준 4초면
끝납니다). `skipped`는 정상입니다 — 대본만 올린 발표라 그릴 슬라이드가 없습니다.

## 2. 커스텀 대본 등록 (대본만 넣기)

```js
async function createCustomScript({ scriptFile, scriptText, topic }) {
  const form = new FormData();
  if (scriptFile) form.append("scriptFile", scriptFile);   // docx/txt/pdf
  if (scriptText) form.append("scriptText", scriptText);   // 직접 입력
  if (topic)      form.append("topic", topic);

  const res = await fetch(`${BASE}/api/presentations/custom`, {
    method: "POST", headers: authHeaders(), body: form,
  });
  const created = await unwrap(res);
  return getPresentation(created.presentationId);          // 같은 이유로 재조회
}
```

## 3. 발음 하이라이팅 대본

**상세 조회 응답에는 하이라이트가 없습니다. 별도 API입니다** — 화면 진입 시 이걸 부르세요.

```js
async function getHighlights(presentationId) {
  const res = await fetch(`${BASE}/api/presentations/${presentationId}/highlights`,
                          { headers: authHeaders() });
  return unwrap(res);
  // result = { presentationId, scripts: [
  //   { scriptId, slideId, content,               // ← 이 문자열 기준 좌표
  //     highlights: [ { highlightId, word,
  //        category,                               // "mismatch" | "liaison" | "length" (소문자)
  //        standardPronunciation, ruleDesc,
  //        positionStart, positionEnd } ] } ] }    // 0-기반, 끝 exclusive
}
```

### 렌더 — ⚠️ 좌표는 그 슬라이드의 `content` 기준입니다

전체 대본을 이어붙인 문자열에 이 좌표를 쓰면 엉뚱한 자리가 칠해집니다.
**scripts 그룹마다, 그 그룹의 content 위에** 칠하세요.

```jsx
const CATEGORY_COLORS = { mismatch: "#e5484d", liaison: "#3b82f6", length: "#f59e0b" };

function HighlightedScript({ group }) {           // group = result.scripts[i]
  const { content, highlights } = group;
  const sorted = [...highlights].sort((a, b) => a.positionStart - b.positionStart);

  const parts = [];
  let cursor = 0;
  for (const h of sorted) {
    if (h.positionStart < cursor) continue;       // 겹침 방어
    parts.push(content.slice(cursor, h.positionStart));
    parts.push(
      <mark key={h.highlightId}
            style={{ background: "transparent", color: CATEGORY_COLORS[h.category],
                     fontWeight: 600, cursor: "pointer" }}
            title={`[${h.standardPronunciation}] ${h.ruleDesc}`}>
        {content.slice(h.positionStart, h.positionEnd)}
      </mark>
    );
    cursor = h.positionEnd;
  }
  parts.push(content.slice(cursor));
  return <p>{parts}</p>;
}

// 사용
{result.scripts.map((g) => <HighlightedScript key={g.scriptId} group={g} />)}
```

## 4. 대본 다운로드

```js
/** kind: "script"(대본) | "highlighted"(발음 리포트) */
async function downloadScript(presentationId, kind = "script") {
  const res = await fetch(
    `${BASE}/api/presentations/${presentationId}/download/${kind}`,
    { headers: authHeaders() });
  if (!res.ok) throw new Error(`다운로드 실패 (${res.status})`);

  const blob = await res.blob();
  const url = URL.createObjectURL(blob);
  const a = Object.assign(document.createElement("a"),
                          { href: url, download: kind === "script" ? "대본.txt" : "발음리포트.txt" });
  a.click();
  URL.revokeObjectURL(url);
}
```

**여기의 `presentationId`가 오늘 문제였던 자리입니다** — 반드시 생성/조회 응답의
`result.presentationId`를 쓰세요 (0번 ID 구분 표 참고).

## 5. 녹음 평가 — ⚠️ 오늘 500 났던 부분

멀티파트 **파트 이름이 정확히 이래야 합니다** (배포 JAR에서 확인한 실제 이름):

```js
async function evaluateRecording({ presentationId, audioFile }) {
  const form = new FormData();
  form.append("file", audioFile);                    // ⚠️ 이름은 "file" (audio ❌ audioFile ❌)
  form.append("presentationId", presentationId);     // ⚠️ camelCase 그대로 (presentation_id ❌)
  // presentationId 대신 scriptFile(파일) 또는 scriptText(텍스트)를 넣을 수도 있지만
  // 발표 자료에서 만든 대본으로 평가하는 일반 흐름에서는 presentationId 하나면 됩니다.

  const res = await fetch(`${BASE}/api/evaluations/record`, {
    method: "POST", headers: authHeaders(), body: form,
  });
  return unwrap(res);
}
```

23:38에 난 500(`presentationId, 대본 파일, 혹은 텍스트 중 하나는 반드시 제공되어야 합니다`)은
**셋 다 안 실려서**입니다. FormData 파트 이름 철자를 위와 똑같이 맞추면 해결됩니다.

- 음성 파일: MP3/WAV, 5초~5분
- 평가는 수십 초 걸립니다 — 로딩 UI 필수

## 6. 발음 듣기 (TTS) — ❌ 지금 붙이지 마세요

백엔드 `AudioController`에 알려진 버그(경로에 없는 `@PathVariable`)가 있어 **어떤 요청이든
500이 납니다.** 백엔드 수정·재배포 후에 붙이세요. 그때의 계약(확정):

```js
async function playPronunciation({ presentationId, word, voice, speed }) {
  const res = await fetch(`${BASE}/api/audio/tts/highlight`, {
    method: "POST",
    headers: { ...authHeaders(), "Content-Type": "application/json" },
    body: JSON.stringify({ presentationId, word, voice, speed }),  // voice·speed는 선택
  });
  if (!res.ok) throw new Error(`발음 재생 실패 (${res.status})`);
  new Audio(URL.createObjectURL(await res.blob())).play();          // 응답은 MP3 바이트
}
```

화자 4명(동현·대성·혜리·고은), 속도 -5~+5(음수가 빠름).
