# 스프링 질문 답변 (2026-08-16)

> 보내주신 코드에 **존재하지 않는 엔드포인트 두 개**가 있어서, 실제 경로와 파라미터를 적습니다.
> 그리고 하이라이팅에 필요한데 AI 서버가 안 주던 값 두 가지를 **오늘 추가**했습니다.

---

## Q1. 커스텀 대본(파일/수기 텍스트) 등록 엔드포인트

**`/api/project/create-custom`은 없습니다.** 새로 만들 필요도 없습니다 —
PPT를 올릴 때 쓰는 **`POST /api/projects`가 그대로 처리합니다.**

```
POST /api/projects        (multipart/form-data)
```

| 경우 | 보낼 것 |
|---|---|
| **수기 텍스트** | `script_text` = 대본 전문 |
| **대본 파일**(docx/txt/pdf) | `file` = 파일 + **`mode=coaching`** |
| (참고) PPT/PDF 발표자료 | `file` = 파일 (`mode` 생략, 기본값 `script`) |

⚠️ 파라미터 이름이 **`text`가 아니라 `script_text`**입니다.
⚠️ 대본 파일은 **`mode=coaching`을 꼭 붙여야** 합니다. 안 붙이면 발표자료(PPT)로 보고
슬라이드를 뽑으려 합니다. `mode=coaching`이면 "이미 완성된 대본"으로 취급합니다.

응답은 PPT 때와 **완전히 같습니다.**
```json
{ "success": true, "project_id": 16,
  "data": { "metadata": {"topic": null, "keywords": []},
            "slides": [{"slide_number": 1, "content": "안녕하세요. 오늘은 ..."}] } }
```
대본만 올린 경우 **슬라이드 1번에 전체 대본이 한 덩어리로** 들어갑니다.
그래서 이후 조회·재생성·녹음·평가가 PPT 있을 때와 **같은 코드로** 돌아갑니다.

> `AiProjectResponseDto`를 새로 만드실 필요 없습니다. `createAiProject()`가 이미
> `Map`으로 받아 `project_id`를 꺼내고 있으니, 그 메서드를 그대로 재사용하시면 됩니다.

## Q2. 발음 하이라이팅을 받아오는 엔드포인트

**`GET /api/project/{id}/highlights`도 없습니다.** 두 가지로 나뉩니다.

### ① 분석을 돌린다 (대본이 바뀔 때마다 한 번)
```
POST /api/analysis/words        Content-Type: application/json
{ "project_id": 16 }
```

### ② 결과를 읽는다 (조회할 때마다)
```
GET /api/projects/{project_id}      →  data.difficult_words
```
①의 응답(`data.words`)에도 같은 값이 들어 있어서, 등록 직후라면 한 번만 불러도 됩니다.

### 응답 — 오늘 필드를 보완했습니다

```json
{
  "word": "책임",
  "phoneme": "[채김]",
  "standard_pronunciation": "채김",
  "category": "연음",
  "category_code": "LIAISON",
  "description": "연음: 앞 받침이 뒤 모음으로 넘어가 발음됩니다.",
  "rule_desc": "연음: 앞 받침이 뒤 모음으로 넘어가 발음됩니다.",
  "occurrences": [
    { "slide_number": 1, "position_start": 4,  "position_end": 6 },
    { "slide_number": 2, "position_start": 11, "position_end": 13 }
  ]
}
```

`PronunciationHighlight` 필드와 이렇게 대응합니다.

| 엔티티 필드 | 쓸 값 |
|---|---|
| `word` | `word` |
| `standardPronunciation` | `standard_pronunciation` |
| `category` | **`category_code`** ← `category` 아님. 아래 설명 |
| `ruleDesc` | `rule_desc` |
| `positionStart` / `positionEnd` | `occurrences[].position_start` / `position_end` |

### ⚠️ `category`가 아니라 `category_code`를 쓰셔야 합니다

지금 코드가 이렇습니다.
```java
category = HighlightCategory.valueOf(categoryStr.toUpperCase());
```
`category`는 **한국어**(`"장단음"`, `"연음"`, `"표기-발음불일치"`)입니다. 한글에는 대문자가
없어서 `valueOf`가 **항상 예외**를 던지고, catch 블록의 기본값(`MISMATCH`)으로 떨어집니다.
**세 카테고리 색이 전부 같아집니다.**

그래서 영문 코드를 따로 추가했습니다. 한국어 이름은 화면에 그대로 뜨는 값이라 못 바꿉니다.

| `category` (화면용) | `category_code` (enum용) |
|---|---|
| 장단음 | `LENGTH` |
| 연음 | `LIAISON` |
| 표기-발음불일치 | `MISMATCH` |

`h.get("category")` → **`h.get("category_code")`** 한 군데만 바꾸시면 됩니다.

### ⚠️ `occurrences`는 **배열**입니다

한 단어가 대본에 여러 번 나오면 자리도 여러 개입니다. `PronunciationHighlight`는 한 행에
좌표가 하나이므로, **occurrence 하나당 한 행**으로 저장하시면 됩니다.

```java
for (Map<String,Object> occ : (List<Map<String,Object>>) h.get("occurrences")) {
    PronunciationHighlight.builder()
        .script(scriptOf(occ.get("slide_number")))   // 그 슬라이드의 Script
        .positionStart(((Number) occ.get("position_start")).intValue())
        .positionEnd(((Number) occ.get("position_end")).intValue())
        …
}
```

좌표는 **그 슬라이드 대본 문자열 기준**입니다(전체 대본 기준 아님). 스프링이 하이라이트를
`Script` 단위로 저장하니 그쪽에 맞췄습니다.

좌표를 **저장해두지 않고 조회할 때마다 다시 계산**합니다. 사용자가 대본을 고치면 저장된
좌표는 즉시 틀린 자리를 가리키기 때문입니다(평가 하이라이팅에서 이미 겪은 문제입니다).
대본이 바뀌면 `occurrences`도 따라 바뀌고, 그 단어가 사라졌으면 **빈 배열**이 옵니다.

## Q3. "AI 대본 듣기"가 전체를 다 읽어주나요?

**아니요. 단어 단위만 있습니다.** 이해하신 게 맞습니다 — **하이라이팅된 단어를 눌렀을 때
그 단어의 표준 발음만** 들려주는 기능입니다.

```
POST /api/tts/word
{ "word": "책임", "project_id": 16 }        → MP3 바이트
```

전체 대본을 읽어주는 API는 **없습니다.** 만든 적이 없고, 지금 우선순위에도 없습니다.

**왜 단어 단위인가.** Clova Voice가 한국어 음운 규칙을 일부만 적용해서, 철자를 그대로 넣으면
**틀린 발음을 정답이라고 들려줍니다.** 실측입니다.

```
역할 → [여칼] ✅ 격음화 적용        권리 → [궐리] ✅ 유음화 적용
각자 → [각자] ❌ 경음화 미적용      책임 → [책임] ❌ 연음 미적용
```

그래서 서버가 G2P로 뽑은 **발음 문자열**을 넣습니다. 전체 대본을 통째로 넣으면 이 교정이
불가능해서(문장 전체의 발음을 다 계산해야 함), 발음 교정 기능으로서 의미가 없어집니다.

`project_id`를 같이 보내면 `/api/analysis/words`가 저장해둔 발음기호를 찾아 씁니다.
화자 목록은 `GET /api/tts/voices`에 있습니다.

## 확인해주신 것 — 저희도 정리했습니다

- **`ai_project_id`** 고치셨다니 감사합니다. 저희가 배포된 JAR을 다시 뜯어봤을 때도
  `createAiProject()`의 저장 경로 자체는 정상이었습니다(`Number` → `longValue()`).
- **`slide_number`** — 전체 대본을 통째로 녹음하는 구조라면 **지금 그대로가 맞습니다.**
  보내지 않으면 AI 서버가 프로젝트의 전체 대본을 기준으로 채점합니다.
- **`grades`** — 계속 int로 받고 계셨다면 그대로 두시면 됩니다.

## 저희가 오늘 배포한 것

- `GET /api/projects/{id}`에 **`full_script`** 추가 (슬라이드 대본을 순서대로 이어붙인 전체 대본).
  지금 `getFullScriptForRecording()`에서 `"\n\n"`으로 직접 이어붙이고 계신데, 그대로 두셔도
  됩니다. 다만 **그 문자열을 `reference_text`로 되보내지는 마세요** — 슬라이드 사이 빈 줄까지
  채점 기준에 들어갑니다.
- 발음 평가 기준 대본에서 `"Slide N:"` 라벨 제거 (라벨까지 '읽어야 할 말'로 채점되던 버그).
- 발음 평가 404 응답에 어떤 `project_id`를 받았는지 적어줍니다.
