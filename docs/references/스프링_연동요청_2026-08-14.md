# 스프링 담당자 전달용 — 대본 코칭·발표 습관 지표 연동 (2026-08-14)

> 아래 본문을 그대로 복사해서 전달하면 됩니다.
> 이전 연동 요청은 [스프링_연동요청.md](스프링_연동요청.md) (2026-08-05) 참고.

---

AI 서버 쪽은 아래 기능이 **전부 구현·검증돼 있습니다.** 스프링에서 중계만 열어주시면 프론트가 바로 쓸 수 있습니다. 각 항목의 요청·응답은 실제로 호출해서 확인한 값입니다.

공통 사항: 모든 AI 서버 호출에 `X-API-Key` 헤더가 필요합니다.

## 1. 대본만 업로드 — 지금 스프링에서 500이 납니다

**증상.** `POST /api/presentations`에 파일 없이 요청하면 500이 납니다. 스웨거 스펙상 `file`이 필수라 **대본만 올리는 경로 자체가 없습니다.**

**AI 서버는 이미 받고 있습니다.** `script_text`를 주면 슬라이드 1번에 전체 대본을 담아 프로젝트를 만듭니다.

```
POST /api/projects        (multipart/form-data)
  project_name = 대본만 코칭
  script_text  = 안녕하세요. 오늘은 ...
```
```json
{ "success": true, "project_id": 16,
  "data": { "metadata": {"topic": null, "keywords": []},
            "slides": [{"slide_number": 1, "content": "안녕하세요. 오늘은 ..."}] } }
```

완성된 대본 파일(DOCX/TXT/PDF)을 그대로 올리는 경로도 있습니다 — `mode=coaching`과 함께 `file`을 보내면 됩니다.

**스프링에서 할 일.** `file`을 선택으로 바꾸고, 없으면 `script_text`를 AI 서버로 넘긴 뒤 응답의 슬라이드 1개를 저장하면 됩니다.

**전체 대본용 테이블은 만들지 않으셔도 됩니다.** AI 서버가 "PPT 있으면 슬라이드별, 없으면 1번 슬라이드에 한 덩어리"로 규칙을 정해뒀습니다. 스프링도 슬라이드 1개짜리 발표로 저장하면 조회·재생성·녹음·평가가 PPT 있을 때와 **완전히 같은 코드로** 돌아갑니다. 테이블을 따로 두면 그 지점마다 분기가 생겨 코드가 두 벌이 됩니다.

참고로 지금 나는 500은 **400이 맞습니다.** 필수 값 누락은 클라이언트 잘못이고, 평가 기준에 "상태코드 의미와 실제 응답 의미가 다름"이 감점 예시로 명시돼 있습니다.

## 2. 대본 수정 저장 — API가 없습니다

**증상.** 편집 화면이 "대본을 직접 수정할 수 있습니다"라고 안내하는데, 스프링에 저장할 엔드포인트가 없습니다. 현재 `PUT`/`PATCH`는 `/api/auth/password`, `/name`, `/email` 셋뿐입니다. 고쳐도 새로고침하면 사라집니다.

**AI 서버 규격.**

```
PUT /api/projects/{project_id}/slides/{slide_number}
Content-Type: application/json
{ "script": "수정된 대본", "source_content": "원문도 함께 고칠 때만(선택)" }
```
```json
{ "success": true, "project_id": 16, "data": { "slides": [ ... ] } }
```

**스프링에서 할 일.** `PATCH /api/presentations/{presentationId}/scripts/{scriptId}` 같은 엔드포인트를 만들고, **스프링 DB와 AI 서버 양쪽에 반영**해주세요.

양쪽에 넣어야 하는 이유가 있습니다. **재생성과 발음 평가는 AI 서버가 들고 있는 대본을 기준으로 동작합니다.** 스프링에만 저장하면 사용자가 고친 대본을 읽고 녹음했는데 서버는 옛 대본으로 채점합니다.

## 3. 상세 피드백 — 호출하는 곳이 없습니다

**증상.** 응답 DTO에 `feedbackDetail` 칸이 있는데 항상 비어 있습니다.

**음성 파일을 다시 보낼 필요가 없습니다.** 평가할 때 Azure가 단어마다 점수를 매겨 저장해뒀기 때문에, 피드백은 그 숫자만 씁니다. 평가 번호 하나만 있으면 됩니다.

```
POST /api/evaluation/{evaluation_id}/feedback      (바디 없음)
```
```json
{ "success": true, "evaluation_id": 12, "cached": false,
  "data": { "summary": "총평 2~3문장",
            "strengths": ["잘한 점 1~3개"],
            "improvements": ["개선할 점 1~3개"],
            "practice_tips": [ { "key": "consonant", "title": "명확한 자음", "description": "..." } ],
            "weak_words": [ {"word": "언제든지", "accuracy_score": 28, "error_type": "Mispronunciation"} ],
            "deductions": { "...": "5번 참고" } } }
```

`practice_tips`는 `consonant / ending / intonation / speed` 네 개가 순서대로 항상 4줄 옵니다(피그마 발음 팁 카드 4개용). 한 번 만들면 저장해두고 재호출 시 캐시를 돌려주므로 HCX 비용은 평가당 한 번만 나갑니다.

**스프링에서 할 일.** `evaluation_id`는 **AI 서버의 번호**입니다. `/api/evaluation/audio` 응답에 들어 있습니다.

가장 간단한 방법은 **평가 직후 그 자리에서 이어 부르는 것**입니다. 컬럼 추가도 새 엔드포인트도 필요 없습니다.

```java
// AI 평가 응답의 evaluation_id로 곧바로
Map fb = restTemplate.postForEntity(
        AI_BASE_URL + "/api/evaluation/" + aiEvaluationId + "/feedback",
        new HttpEntity<>(null, headers), Map.class).getBody();
evaluation.setFeedbackDetail(toJson(fb.get("data")));
```

이미 2분 넘게 걸리는 요청이라 몇 초 더 붙어도 체감 차이가 없습니다. 나중에 따로 받는 구조로 가시려면 AI 서버의 `evaluation_id`를 저장할 컬럼이 하나 필요합니다.

## 4. 간투어·멈춤 — 칸은 있는데 채울 데이터가 없었습니다

응답 DTO에 이미 자리가 있습니다.

```
fillerWordCount   fillerWordDetail   pauseScore   pauseDetail
```

**AI 서버에 계산 기능이 아예 없어서** 비어 있던 것이고, 지금 만들었습니다([PR #40](https://github.com/chiung22/SpeaKO/pull/40)). 머지·배포 후 `/api/evaluation/audio` 응답에 `speech_metrics`가 함께 옵니다.

```json
"speech_metrics": {
  "filler_words": { "count": 3, "by_word": [{"word":"음","count":2}],
                    "occurrences": [{"word":"음","word_index":4,"offset_seconds":12.3}],
                    "spoken_word_count": 88, "ratio_percent": 3.4 },
  "pauses": { "available": true, "threshold_seconds": 0.7, "count": 2,
              "total_seconds": 3.4, "longest_seconds": 2.1,
              "items": [{"after_word":"습니다","start_seconds":12.9,"duration_seconds":2.1}] },
  "speech_rate": { "available": true, "speaking_seconds": 55.2, "words_per_minute": 130.4 }
}
```

**매핑.**

| AI 서버 | 스프링 |
|---|---|
| `speech_metrics.filler_words.count` | `fillerWordCount` |
| `speech_metrics.filler_words` (JSON 문자열) | `fillerWordDetail` |
| `speech_metrics.pauses` (JSON 문자열) | `pauseDetail` |

**`pauseScore`는 대응하는 값이 없습니다.** AI 서버는 멈춤 횟수·총 시간·최장 시간을 주는데, 그걸 몇 점으로 환산할지는 정해진 규칙이 없습니다. **이 필드의 의미를 먼저 정해주세요.** (예: 100점에서 멈춤 1회당 5점 감점, 하한 0점)

`pauses.available`이 `false`면 시간 정보를 못 받은 경우입니다. 0으로 표시하지 마시고 "측정 안 됨"으로 구분해주세요.

## 5. 결과창 빨간 하이라이팅 + 감점 요인 (2026-08-15 추가)

**틀린 워딩을 빨간색으로 칠하고, 왜 깎였는지 상세 피드백에서 설명한다** — 기획 확정 사항입니다. 프론트가 규칙을 다시 세우지 않도록 **AI 서버가 색 단계까지 정해서** 내려줍니다.

`/api/evaluation/audio` 응답에 두 칸이 추가됩니다.

```json
"highlights": {
  "reference":  [ {"word":"인프라","start":12,"end":15,"type":"omission",
                   "level":"error","reason":"대본에 있지만 말하지 않았습니다.","accuracy_score":0} ],
  "recognized": [ {"word":"음","start":6,"end":7,"type":"insertion",
                   "level":"error","reason":"대본에 없는 말을 했습니다.","accuracy_score":0} ],
  "counts": {"omission":5,"insertion":1,"mispronunciation":2,"error":6},
  "has_errors": true
}
```

**`level`이 `"error"`인 것만 빨간색입니다.**

| type | 뜻 | level | 색 |
|---|---|---|---|
| `omission` | 대본에 있는데 안 읽음 | `error` | 🔴 빨강 |
| `insertion` | 대본에 없는데 말함 | `error` | 🔴 빨강 |
| `mispronunciation` | 읽긴 했는데 발음이 흐림 | `warning` | 빨강 아님 |

발음이 흐린 건 **단어를 틀리게 읽은 게 아니라서** 같은 빨강으로 칠하면 "대본을 틀리게 읽었다"는 잘못된 인상을 줍니다. 색은 프론트가 정하되 `error`와 `warning`은 반드시 구분해주세요.

`start`/`end`는 **응답의 `reference_text` / `recognized_text` 기준 문자 오프셋**입니다. 대본을 이어붙일 때 `"Slide N:"` 접두어가 붙으므로, 프론트가 따로 들고 있는 원본 문자열로 자르면 엉뚱한 글자가 빨개집니다. **두 텍스트를 반드시 같이 내려주세요.** 위치를 못 찾은 단어는 목록에서 빠집니다(엉뚱한 곳을 칠하느니 안 칠합니다) — `counts`와 목록 길이가 다를 수 있는 건 그래서입니다.

**감점 요인 (`deductions`)** — "무엇 때문에 깎였는가"입니다. 상세 피드백(3번)이 이걸 근거로 문장을 씁니다.

```json
"deductions": {
  "factors": [
    { "key":"omission", "label":"대본 누락", "count":5, "ratio_percent":55.6,
      "affects":["completeness"], "severity":"high",
      "examples":["인프라","첫째로","확장성이"],
      "message":"대본에 있는 단어 5개를 읽지 않았습니다(대본의 55.6%). 완성도 점수가 그만큼 내려갑니다." }
  ],
  "counts": {"omission":5,"insertion":1,"mispronunciation":2,"filler":1,"pause":1},
  "scores": {"accuracy":72,"fluency":64,"completeness":40,"pronunciation_score":58},
  "primary": "omission"
}
```

`factors`는 **심각한 순으로 정렬**돼 있고, `message`는 **완성된 문장**이라 그대로 화면에 띄우면 됩니다. HCX 피드백을 안 불렀거나 실패해도 감점 요인 카드는 그릴 수 있습니다. `key`는 `omission / insertion / mispronunciation / filler / pause / speech_rate` 여섯 가지입니다.

**⚠️ 요인별로 몇 점이 깎였는지는 안 내려갑니다.** Azure가 공개하지 않는 값이라 지어낼 수 없습니다. 화면에 "누락 −12점"처럼 쓰지 마시고, `affects`가 가리키는 점수를 `scores`에서 꺼내 **"완성도 40 — 대본 누락 5개 때문입니다"** 형태로 이으시면 됩니다.

**매핑.**

| AI 서버 | 스프링 |
|---|---|
| `highlights` (JSON 문자열) | 새 칸 필요 — 없으면 `words_detail`을 그대로 넘기고 프론트가 계산 |
| `deductions` (JSON 문자열) | `feedbackDetail`에 같이 넣거나 새 칸 |
| `deductions.counts.omission` / `.insertion` | 뱃지용 숫자 |

**조회 API에도 실립니다.** 지난 평가를 다시 열어도 같은 자리가 빨개져야 하므로:

- `GET /api/projects/{id}` → `evaluations[].highlights` (전체 목록 + 위치)
- `GET /api/evaluations` → `highlight_counts` (개수만. 목록 화면 뱃지용)
- `POST /api/evaluation/{id}/feedback` → `data.deductions` (캐시된 옛 피드백에도 채워서 나갑니다)

## 5-1. 점수가 정수로 바뀌었습니다 (2026-08-15)

**등급(`grades`) 필드를 없앴고, 점수는 0~100 정수로 내려갑니다.** 소수점도 없어졌습니다.

```json
"overall_scores": { "accuracy": 87, "fluency": 82, "completeness": 95, "pronunciation_score": 84 }
```

| 전 | 후 |
|---|---|
| `"accuracy": 87.4` | `"accuracy": 87` |
| `"grades": {"accuracy": "B", ...}` | **필드 자체가 없음** |

스프링 DTO의 점수 필드가 `Double`/`Float`이면 정수를 받아도 문제없지만, **`grades`를 매핑하고 있었다면 그 코드는 지워야 합니다.** `words_detail[].accuracy_score`도 같이 정수가 됐습니다.

DB에 이미 저장된 소수 점수는 그대로 두셔도 됩니다 — AI 서버가 조회할 때 정수로 맞춰서 내보냅니다.

## 6. 아직 중계가 없는 것 (참고)

시연 범위에 넣으실 거면 엔드포인트가 필요합니다. 전부 AI 서버에는 이미 있습니다.

| 기능 | AI 서버 |
|---|---|
| 발음 주의 단어 (편집 화면에서 미리 짚어주는 단어. 5번의 채점 하이라이팅과 다릅니다) | `POST /api/analysis/words` |
| 목소리 목록 | `GET /api/tts/voices` |
| 단어 발음 듣기 (MP3) | `POST /api/tts/word` |
| 대본 DOCX 내려받기 | `GET /api/projects/{id}/script.docx` |

그리고 발표 조회 응답의 `slideTitle`과 `rawText`가 **항상 null**입니다. AI 서버는 슬라이드 원문을 `source_content`로 들고 있고 `GET /api/projects/{id}`로 내려줍니다. 새 컬럼이 아니라 **기존 컬럼을 안 채우고 있는 것**이라, 저장 시점에 받아 넣으시면 됩니다.

## 검증 내역 (2026-08-14)

대본만 올려서 음성 코칭까지 가는 전 경로를 AI 서버에서 직접 호출해 확인했습니다.

```
1) POST /api/projects (script_text)          → 200, project_id 발급, 슬라이드 1개
2) GET  /api/projects/{id}                   → 200, slides[0].script에 대본 저장 확인
3) PUT  /api/projects/{id}/slides/1          → 200, 수정 내용 반영 확인
4) POST /api/evaluation/audio (project_id만) → 200, 점수 + speech_metrics 반환
```

4번은 `slide_number` 없이 불러도 프로젝트 전체 대본을 기준으로 채점합니다. 슬라이드가 하나뿐이니 결과가 같습니다.

**주의 한 가지.** 대본만 올린 경우엔 나눠 녹음할 단위가 없어 통째로 올리게 됩니다. 실측으로 3,590자 기준 **2분 28초** 걸렸고, AI 서버에 15분 길이 상한이 있습니다. 시연에서 이 경로를 보여주실 거면 짧은 대본으로 하시는 편이 안전합니다.
