# 스프링 담당자 전달용 — AI 서버 연동 확인 요청 (2026-08-05)

> 아래 본문을 그대로 복사해서 전달하면 됩니다. 근거와 실측 내용은 [nextStep.md](../../nextStep.md)의 "🔌 스프링·프론트 연동" 절 참고.

안녕하세요! AI 서버(FastAPI) 쪽 작업이 마무리돼서, **스프링에서 확인해주셔야 할 것들**을 정리해 보냈습니다.

구조가 `프론트 → 스프링 → AI 서버`라서, AI 서버가 잘 동작해도 스프링에서 막히면 원인을 찾기가 어렵습니다. AI 서버 쪽은 전부 테스트하고 실제로 띄워서 확인했습니다(테스트 195건 통과). 아래는 **스프링에서만 확인 가능한 부분**입니다.

## 🚨 이건 안 고치면 시연 때 바로 막힙니다 (2개)

### 1. multipart 업로드 크기 올려주세요

Spring Boot 기본값이 **파일 1MB / 요청 10MB**인데, AI 서버는 **20MB PPT**를 받도록 되어 있습니다.
지금 상태면 **PPT 업로드가 스프링에서 막혀서 AI 서버에 오지도 않습니다.**

```properties
spring.servlet.multipart.max-file-size=25MB
spring.servlet.multipart.max-request-size=30MB
```

### 2. `202` 상태코드를 그대로 내려주세요

대본 생성은 20~30초 걸려서, 요청을 붙잡지 않고 **접수번호만 먼저 주는 방식**입니다.

```
POST /api/script/full   →  202 + { "job_id": "..." }     ← 접수만 됨
GET  /api/script/jobs/{job_id}  →  { "status": "processing" | "completed" | "failed" }
```

프론트는 **`202`를 보고 폴링을 시작**합니다. 스프링이 이걸 `200`으로 바꾸면 프론트가 폴링을 안 해서 **대본 생성이 영원히 안 끝난 것처럼 보입니다.**

`GET /api/script/jobs/{id}`도 그대로 통과시켜 주세요. 프론트가 1~2초마다 호출합니다.

그 외 `413`(크기 초과) / `422`(잘못된 입력) / `429`(요청 과다) / `502`(외부 AI 실패)도 그대로 내려주시면 됩니다. 200이나 500으로 바꾸면 프론트가 사용자에게 맞는 안내를 못 합니다.

## ⚠️ 이건 혼자 테스트할 땐 안 드러나고, 시연 당일에만 터집니다

### 3. `X-Forwarded-For` 헤더를 넘겨주세요

AI 서버에 요청 횟수 제한이 있습니다(유료 AI API 비용 방어용, **분당 60건**).

이걸 클라이언트 IP 기준으로 세는데, 스프링을 거치면 **모든 요청이 스프링 서버 IP 하나로 보입니다.** 그러면 접속한 전원이 분당 60건을 나눠 쓰게 되어, 여러 명이 동시에 쓰는 시연 상황에서 서로 막힐 수 있습니다.

`X-Forwarded-For`를 그대로 넘겨주시면 사용자별로 따로 셉니다.

## 📌 나머지 (확인만 부탁드립니다)

- **`X-API-Key`** — AI 서버 인증 헤더입니다. 프론트에서 받은 걸 넘기시든 스프링이 서버 키를 넣으시든 상관없는데, 없으면 전부 `401`입니다.
- **`Retry-After`** — `429` 응답에 "몇 초 뒤 재시도" 값이 초 단위로 붙습니다. 프론트가 이 값을 쓰니 삼키지 말아주세요.
- **타임아웃** — `POST /api/evaluation/audio`(발음 평가)만 Azure 왕복이라 **수십 초** 걸릴 수 있습니다. 이 경로만 읽기 타임아웃을 60초 이상으로 잡아주세요. 대본 생성은 위 202 방식이라 요청 자체는 짧습니다.
- **인코딩** — 오류 메시지가 한국어입니다. AI 서버가 `charset=utf-8`을 명시해서 내려보내니 중간에서 다시 인코딩하지 말아주세요.
- **CORS** — 프론트가 스프링만 부르는 구조면 AI 서버 CORS는 상관없고 스프링 쪽 설정만 있으면 됩니다. 혹시 프론트가 AI 서버를 직접 부르는 구간이 있으면 알려주세요, 도메인 등록하겠습니다.

## 확인해보실 때

AI 서버 API 명세는 `frontend-api-guide.md`에 정리돼 있습니다. 응답 상한값(글자 수, 파일 크기, 요청 횟수)도 표로 있습니다.

빠르게 확인하시려면 이 순서가 좋습니다.

1. 15~20MB PPT 업로드 → `200`이 오는지 (1번 확인)
2. 대본 생성 요청 → 응답 코드가 `202`이고 본문에 `job_id`가 있는지 (2번 확인)
3. 그 `job_id`로 폴링 → `status`가 `processing`에서 `completed`로 바뀌는지

막히는 부분 있으면 알려주세요!
