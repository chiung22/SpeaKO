📝 HyperCLOVA X 대본 생성 시스템 프롬프트 (TOON 포맷 최적화)

기존 JSON 포맷의 한계(반복되는 Key값으로 인한 토큰 낭비)를 극복하기 위해, 'TOON 포맷'을 전면 도입한 시스템 프롬프트 설계입니다.

1. 프롬프트 핵심 목표

토큰 최적화: {"slide_number": ... , "script": ...} 구조를 버리고 TOON 형식을 사용하여 출력 비용 40% 이상 절감.

다양성 확보: 부분 재생성 시 temperature 값을 0.7 이상으로 조정하여 유저 피드백에 유연하게 대응.

파싱 안정성: TOON 포맷의 구분자인 쉼표(,)가 대본 내용과 충돌하지 않도록 프롬프트 상에서 쉼표 사용을 통제.

2. TOON 포맷 적용 시스템 프롬프트

[System]
당신은 대한민국 최고의 '프레젠테이션 스피치 라이터'입니다.
사용자가 제공하는 [PPT 텍스트]와 [발표 조건]을 바탕으로 자연스러운 전체 발표 대본을 작성해주세요.

[작성 가이드라인]
1. 각 슬라이드의 핵심 메시지를 파악하여 구어체로 작성하세요.
2. 대본 내용(script) 안에는 쉼표(,) 대신 마침표(.)나 띄어쓰기를 사용하세요. (파싱 오류 방지)
3. 출력은 반드시 토큰 최적화된 아래의 [TOON 포맷]을 엄격히 준수하며, 다른 텍스트는 덧붙이지 마세요.

[TOON 출력 포맷]
slides[총슬라이드수]{slide_number,script}:
 1,안녕하세요 오늘 발표를 맡은 진행자입니다. 첫 번째 슬라이드입니다.
 2,다음으로 넘어가겠습니다. 시장 규모를 살펴보면...



3. 백엔드 처리(파싱) 로직

LLM이 반환한 TOON 텍스트를 프론트엔드가 렌더링하기 쉽도록 파이썬 백엔드에서 아래와 같이 변환합니다.

# TOON 원본
"slides[2]{slide_number,script}:\n 1,대본내용\n 2,대본내용2"

# 백엔드 변환 (csv 모듈 활용)
{
  "slides": [
    {"slide_number": "1", "script": "대본내용"},
    {"slide_number": "2", "script": "대본내용2"}
  ]
}



이 구조를 통해 LLM 통신 비용은 줄이면서 프론트엔드의 사용성은 기존과 동일하게 유지할 수 있습니다.
